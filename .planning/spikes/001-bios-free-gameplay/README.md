# Spike 001: BIOS-free GB/GBC gameplay

## What This Validates

The installed, digest-verified **mGBA 0.10.5 Qt binary** boots three self-authored cartridge fixtures without any BIOS. Its real GB core executes game code, renders a 160×144 screen, and responds to an A-button edge. This is emulator feasibility, not a new Playstead support claim or physical-controller qualification.

## Research

Checked the [official 0.10.5 release](https://mgba.io/2025/03/08/mgba-0.10.5/), the tagged [GB core](https://github.com/mgba-emu/mgba/blob/0.10.5/src/gb/core.c), [Qt input defaults](https://github.com/mgba-emu/mgba/blob/0.10.5/src/platform/qt/InputController.cpp), [tagged scripting implementation](https://github.com/mgba-emu/mgba/blob/0.10.5/src/core/scripting.c), and [scripting API](https://mgba.io/docs/scripting.html). The tag confirms the APIs used by the test, rather than assuming current documentation describes this binary.

| Input/observation approach | Advantage | Limitation | Result |
|---|---|---|---|
| Native automated X key and F12 | Ordinary Qt keyboard route and raw screenshot | Short injected presses did not change the counter reliably | Screenshots worked; input inconclusive |
| Lua A-button edge held for frames; RAM read and screenshot | Bounded, repeatable core input plus independent rendered oracle | Does not prove Qt keyboard timing, OS HID or hardware | Chosen; counter and exact pixels agree |

The native Qt binary is the target. A separately compiled headless or SDL core would have different binary lineage and is not a substitute for this proof. `useBios=0` is explicit, the isolated configuration initially has no BIOS, and no `-b` argument is supplied. `XDG_CONFIG_HOME` isolates Qt/core settings without replacing the owner's HOME.

## How to Run

From the repository root:

```sh
python3 .planning/spikes/001-bios-free-gameplay/build_fixture.py --out playstead-mac/.local/gb-gbc-spike/fixtures
python3 .planning/spikes/001-bios-free-gameplay/probe.py run gb-mbc1-8k
```

Run one emulator at a time; select the already-running exact bundle before UI operations. The emulator is interactive: X is the default A binding. For deterministic automation use Tools → Scripting, then paste the command generated by:

```sh
python3 .planning/spikes/002-persistent-battery-saves/oracle_command.py gb-mbc1-8k new-label
```

The same commands accept `gbc-mbc5-32k` and `gbc-mbc3-rtc`. Keep labels unique. Clean quit with Cmd-Q; the probe waits for actual exit and logs its status. It bounds each run to 300 seconds and cleans up its own executable on interruption. The committed PNGs can be inspected without launching anything.

## What to Expect

PLAYSTEAD, GB or GBC, SAVE, a hexadecimal counter, and A SAVE. GB glyphs are black; GBC glyphs are red. Boot reads existing battery bytes without writing a new counter. Each new A edge increments the counter once.

## Observability

`probe.py` exports timestamped launch, save-size/prefix changes, exit and cleanup events under the ignored `.local/gb-gbc-spike/<fixture>/` tree. Completed runs are preserved in `runs/`. Executable SHA-256 must match before launch. The checked-in evidence contains sanitized receipts and raw emulator screenshots, not owner content.

`verify_pixels.py` decodes PNG with the Python standard library, checks CRC/format, compares all **23,040 pixels** to the authored font/map/counter, and requires the red GBC palette. Missing or malformed images and wrong counters fail. It does not infer success from a window title or FPS.

## Investigation Trail

1. Reused existing pinned installation and GBA prior art. Existing AerevenAdvance registry is present; it remains a GBA continuity fixture and was not modified or substituted with another owner ROM. No existing GB/GBC fixture was found in the local fixture/spike directories.
2. Authored 32 KB ROMs using a small Python opcode emitter and original font/game behavior. Standard cartridge recognition bytes are format metadata; no commercial game or proprietary BIOS was fetched.
3. Fixed a generator checksum overflow before launch. Refined input polling from once per VBlank to continuous sampling after short automated keypresses failed. Neither failed attempt counted as an input pass.
4. Held A through the actual shipped scripting API, rather than writing the counter or save bytes from the oracle. GBC monochrome development output was refined to a red palette, making color execution observable.
5. Cross-checked RAM counters against raw exact-pixel screenshots for GB MBC1/8 KB, GBC MBC5/32 KB, and GBC MBC3/RTC. Save continuity is documented separately in Spike 002.

## Results

**VALIDATED**, scoped to these three authored fixtures and the installed 0.10.5 binary. GB and GBC boot BIOS-free, render correct content, and execute input-driven gameplay. Keyboard automation remains inconclusive; no physical input claim is made. Other cartridge types, hybrid/dual-mode titles, audio quality and commercial-title compatibility were not qualified.

See [evidence](evidence.json), [fail-closed controls](verification-controls.json) and the committed `evidence/` PNGs. Pixel comparison covers every position in the authored tile mask, with a separate red-palette requirement for GBC. Production adapter pin, catalog and support matrix remain unchanged.
