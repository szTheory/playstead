<objective>
Preserve a safe, actionable Linux restore stage when the isolated fixture fails, and make that evidence survive GitHub Actions' normal failure-step skipping behavior.

Purpose: Exact-head run 36931486120 on `3f2316d0a99ca0aff09da789dd1ea690d4bae8ab` passed Linux compilation and privacy/lifecycle contracts, then failed at `Run isolated restore fixture`. The ordinary sanitizer and upload were skipped. The wrapper currently writes private Mix output to a mode-700 temporary directory and logs only a fixed stage, but creates its success receipt only on pass; the sanitizer accepts only that passing receipt. The underlying fixture failure therefore has no safely persisted stage artifact. Do not inspect runner logs or infer the failing operation from the step result.

Output: A distinct fixed-enum failure document, fail-closed sanitization and negative synthetic coverage, post-failure GitHub Actions publication that preserves the failed job status, and exact-head hosted evidence. Keep existing passing receipt bytes/schema contract unchanged and add no dependency. From security/privacy, CI/SRE, product reliability, and maintenance perspectives, prefer one closed stage token over raw traces: it gives maintainers a next investigation point, keeps the red check visible, and uses the existing Python/shell/GitHub Actions path instead of another package or diagnostic abstraction. The resulting reduction in detail is intentional: unknown failures remain classified as `unknown` and non-passing.
</objective>
