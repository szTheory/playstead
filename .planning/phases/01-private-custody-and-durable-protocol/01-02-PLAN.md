Build the bootstrap in `Playstead.Setup`. `mint_token/0` runs from the application supervision tree after the Repo starts: if `Playstead.Accounts.owner_exists?/0` is true it is a no-op; otherwise it generates 32 bytes from `:crypto.strong_rand_bytes/1`, base64url-encodes them without padding, stores only the SHA-256 hash in a `setup_tokens` row, and prints the plaintext to stdout inside a visually obvious banner so a self-hoster can find it in `docker compose logs`. `claim/2` performs the once-only owner-creation transition inside a single `Ecto.Multi`: verify the token, insert the owner via `Accounts.register_owner/1`, mark the setup-token row consumed, and generate the recovery codes — all in one transaction, guarded by a unique constraint that makes a second concurrent claim fail rather than create a second owner. `Playstead.Readiness.summary/0` returns an ordered, fixed list of three check rows:

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous browser → `/setup` | Untrusted visitors reach the claim surface before an owner exists |
| Anonymous browser → `/log-in` | Untrusted credential submission |
| Host operator → container stdout | The setup token crosses here; host access is the root of trust |
| LiveView console → Accounts context | Authenticated commands cross into domain code carrying a Scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-08 | Elevation of Privilege | `/setup` claim window | critical | mitigate | A single-use 256-bit setup token, stored hashed, is required before owner creation; `/setup` 404s permanently once an owner exists; there is no unauthenticated first-visit claim path at any moment (D-03, task 2) |
| T-01-09 | Elevation of Privilege | Concurrent setup claims | high | mitigate | `claim/2` runs in one `Ecto.Multi` with a unique constraint so two concurrent claims yield exactly one owner; the loser receives a token-already-used error (task 2) |
| T-01-10 | Spoofing | Password authentication | high | mitigate | bcrypt hashing via the phx.gen.auth default, constant-time comparison, generic bad-credentials copy that does not distinguish unknown-user from wrong-password (task 1); per-IP and per-account throttling lands in plan 01-03 |

| T-01-13 | Tampering | Readiness HTTPS reporting | medium | mitigate | The four transport states are reported distinctly; plain-HTTP and external-proxy states are never labelled secure (task 2) |
