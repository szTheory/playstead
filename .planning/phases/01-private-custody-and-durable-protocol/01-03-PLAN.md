<objective>
Make the owner's own credentials revocable, recoverable, and hard to brute-force — without email, and without silently breaking a LAN plain-HTTP deployment.

Purpose: D-06's insight is that sessions and paired devices are one mental model — revocable credentials. This plan builds the session half and the sudo-mode gate that plan 01-05's device revocation reuses, plus the two email-free recovery paths so a locked-out owner is never stranded.

Output: a Sessions list with per-session revocation, a sudo-mode re-authentication gate, scheme-aware cookie posture, login throttling, an append-only audit log, a Mix-release reset command, and recovery-code login.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous browser → login / recovery routes | Untrusted credential and recovery-code submission |
| Host operator → release command | The reset URL crosses here; host access is the root of trust |
| Authenticated console → dangerous actions | Sudo-mode gate separates ordinary console use from credential-affecting commands |
| Browser cookie ↔ session token row | The revocable credential boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-14 | Spoofing | Session cookie theft | high | mitigate | `HttpOnly` + `SameSite=Lax` always, `Secure` when the scheme is HTTPS, DB-backed revocable session tokens, and a Sessions list that makes an unexpected session visible and killable (task 1) |
| T-01-15 | Elevation of Privilege | Dangerous console actions | high | mitigate | Sudo-mode re-authentication with a bounded freshness window gates session revocation and recovery-code regeneration, and is reused by plan 01-05 for device revocation (task 1) |
| T-01-16 | Spoofing | Credential brute force | high | mitigate | Fixed per-IP and per-account throttling on login, sudo, and recovery-code submission via `hammer`; generic failure copy that does not distinguish failure causes (task 1) |
| T-01-17 | Elevation of Privilege | Reset-URL interception | high | mitigate | Single-use, short-expiry, hash-stored reset token printed only to container stdout; issuing it deletes every existing session so a reset cannot be used to run alongside a stolen one (task 2) |
| T-01-18 | Repudiation | Credential-affecting events | medium | mitigate | Append-only `Playstead.AuditLog` with no update or delete path records session revocation, sudo confirmation, reset issuance, and recovery-code consumption (tasks 1 and 2) |
| T-01-19 | Information Disclosure | Session client labels | low | mitigate | Raw user-agent strings are not persisted when unrecognizable; the UI renders a generic label rather than echoing attacker-controlled text (task 1) |
| T-01-20 | Denial of Service | Throttle exhaustion locking out the owner | medium | accept | Fixed limits with a short window are used deliberately instead of adaptive lockout (D-06); the host-side reset command remains available as an out-of-band path that no network attacker can throttle |
</threat_model>
