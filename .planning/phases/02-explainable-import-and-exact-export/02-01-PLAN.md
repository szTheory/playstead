Add three readiness rows to `summary/1`, each following the existing `%{id:, state:, message:}` shape and the existing `:ok | :warning | :error` state vocabulary — do not invent a fourth state or a parallel health module.

Row one, id `:inbox`: reads `PLAYSTEAD_INBOX_PATH` defaulting to `/app/inbox`. Row two, id `:exports`: reads `PLAYSTEAD_EXPORT_PATH` defaulting to `/app/exports` and reuses the existing `writable_check/1` probe unchanged, since this mount genuinely must be writable per D-33.

Add a public `free_bytes/0` returning available bytes on the blob volume as an exact integer from a live filesystem statistics call, and a public helper that answers whether a requested byte count fits the D-10 rule: required space is the requested bytes plus the larger of 1 GiB and five percent of the volume's capacity. Compute this entirely in integer arithmetic — no floats, no `round/1`, no division that loses a remainder — because a rounding error here means admitting a write that then fails mid-file. A request needing exactly the available margin passes; one byte more is refused. Both functions are public because the IMPT-01 preview, the per-write preflight, and this readiness row must all read the same number from the same code.
