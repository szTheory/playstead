Give the custody pipeline eyes: pure, bounded, never-raising validators for the seven supported systems, an evidence-only recognition provider that works with no reference data installed, honest display titles, and ordered multi-file manifests so a two-file PlayStation game is one game with a missing part rather than two mystery files.

Purpose: IMPT-03's receipt taxonomy and IMPT-04's explicit manifests both depend on the server being able to say something true and bounded about untrusted bytes. This is also where the phase's parser attack surface lives, so every validator here is written to the same rules: at most 64 kibibytes read, pure binary pattern matching, no native code, and a tagged result rather than an exception for every input including deliberately malformed ones.

Output: the frozen system registry, six validators with adversarial fixtures, archive magic detection that keeps containers opaque, the recognition provider behaviour and its built-in header-evidence implementation, No-Intro filename parsing, system assignment with recorded provenance, ordered multi-file sets, and the frozen catalogue journal payload.

Create `Playstead.Formats.SystemId` by copying the `Playstead.Sync.EntityKind` shape exactly — a module attribute list, `all/0`, and `valid?/1` clauses for atom and string with a catch-all false. The members are `gba`, `gb`, `gbc`, `nes`, `snes`, `md`, `psx`, and `unknown`. Document in the moduledoc that these strings are published vocabulary because they appear in export manifests and in the client change journal, and that adapter-facing names such as emulator core identifiers or launcher folder names are a client-side mapping and never server truth.

Create one validator module per system under `lib/playstead/formats/validators/`, each exposing a `recognize/1` taking a binary and returning either a tagged match carrying an evidence map or a no-match result. Every validator obeys the same four rules, which are the phase's parser safety contract and not stylistic preferences. First, read at most the first 64 kibibytes; a caller may pass more and the validator must simply not look past that bound. Second, pure Elixir binary pattern matching only — no native implemented function, no port, no external command. RESEARCH is explicit about why: a malformed input that crashes native code takes the whole runtime node down, whereas a pattern match that fails is an ordinary Elixir value. Third, never raise for any input; guard every arithmetic operation and every sub-binary extraction so that empty, truncated, and randomly mutated bytes all produce a no-match result. Fourth, record the tier as part of the evidence so a consumer can tell a signature-confirmed result from a structural heuristic — the tier is evidence about the confidence of the reading, never a verdict about the legitimacy of the bytes.

The signature-validated group is GBA, Game Boy and Game Boy Color, NES, and Mega Drive: each confirms a fixed magic or logo signature plus its header checksum or complement relationship, and reports the header fields the recognition provider will use as evidence — the GBA title and game code, the Game Boy flags including colour capability, the NES mapper and header generation, and the Mega Drive serial and region. The structure-validated group is SNES and the PlayStation CUE descriptor: SNES has no magic signature, so it applies the internal checksum and complement relationship and the 512-byte copier-header offset rule, and its evidence must carry the structural tier so no consumer mistakes it for a confirmed signature. The CUE validator parses the descriptor as text under hard caps — at most 64 kibibytes of text, at most 99 file or track entries, the binary file type only, and referenced names that are bare relative names with no parent-directory segment, no path separator, and no control characters. The `.chd` case reads the container header only; there is no hunk decompression anywhere.

Create `Playstead.Formats.Archive` detecting the zip, 7z, rar, gzip, xz, and zstd signatures from leading magic bytes. Detection stops there: it reports that the file is a container and nothing else. No entry is listed, no central directory is read, no byte is decompressed, and no declared internal size is ever read — declared sizes lie, which is exactly why the archive-security gate is a separate deferred spike with its own adversarial corpus and isolation requirements. Detection is by magic bytes and never by extension, so a renamed archive is still recognised and a ROM with a misleading extension is still read as a ROM.

Create `Playstead.Formats.identify/2` as the single entry point taking the leading bytes and the original filename and returning the system identifier, the tier, and the evidence map, with archives short-circuiting to a container result and everything else falling through to the unknown identifier with no claim made.

Build the fixture corpus under `test/support/fixtures/roms/`: for each validated system a minimal byte sequence with a correct header, plus deliberately broken variants — truncated before the header ends, correct signature with a wrong checksum, and one system's header wearing another's file extension. Add CUE fixtures containing a parent-directory reference, an absolute path, a Windows drive-letter path, an embedded NUL byte, and more entries than the cap. Add archive fixtures for each magic signature including one carrying a valid ROM header before its archive signature. Write one test file per validator plus the archive test, and add a `stream_data` property test asserting that for arbitrary binaries of arbitrary length every validator returns a value and never raises.

Implement `Playstead.Recognition.HeaderEvidence` as the built-in provider that needs no reference data at all. Implement the three frozen relationship definitions exactly as D-17 states them and no more strongly.
