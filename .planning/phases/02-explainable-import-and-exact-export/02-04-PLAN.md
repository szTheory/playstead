<objective>
Make the moment before a copy honest. A user drops a file into the console, and before a single byte moves they see its exact size, that a verified copy will be stored by their server, that their original stays exactly where it is, and what that will cost in free space. Afterwards they can look at the stored asset and read its exact size, its full SHA-256, and where it came from.

Purpose: IMPT-01 and IMPT-02 are the two requirements a first adopter judges the product's honesty by. The failure mode is not a crash — it is a plausible-looking screen that overstates what is known before hashing, or a completed import whose evidence is not actually inspectable afterwards. Both are avoided by computing the preview only from what is knowable before bytes move, and by rendering every post-import claim from the durable receipt.

Output: the streaming hashing upload writer, the pre-copy preview, the import console with its receipt list, and the library asset detail view where hash, size, and provenance live.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → LiveView upload | Chunked upload bytes, the declared filename, and the declared size are untrusted |
| stored evidence → rendered console | Filenames, titles, and provenance strings originating from untrusted input are rendered back to a browser |
| user A's session ↔ user B's data | The console renders per-user views over a globally shared blob store |
