<objective>
Close the loop on lock-in. A user exports their library into ordinary folders on a disk they control, verifies it with `sha256sum` and nothing else, and — if they ever wipe the server — reimports it to get the same games back with the same identifiers, the same relationships, and not one duplicate record.

Purpose: PORT-02 is the requirement that makes every other promise in this phase checkable by the user rather than merely asserted by the product. It is also where the two most dangerous bugs in the phase live: a path built from a client-supplied filename that escapes the export root, and a reimport that trusts an identifier in a file it just read from disk. Both are handled structurally — one sanitizer at every write, and identity decided by hashes before any sidecar is consulted.

Output: the deterministic BagIt layout with sidecars, the write-then-verify resumable export worker, the exports console and API, hash-set-first reimport identity, and the five round-trip contract assertions.
</objective>
