<objective>
Make a big collection import survivable. A user copies a few hundred gigabytes into a host folder, stages it with one explicit action, sees what is about to happen, starts it, walks away, comes back to bounded progress, pauses it, resumes it after a server restart, retries the handful that failed, and re-runs the scan without re-copying a single unchanged byte.

Purpose: IMPT-05 is where every durability decision in this phase gets tested for real. The failure modes are specific and unforgiving — a pause that pauses everyone's work, a resume that starts over, a reconcile that duplicates, a disk-full that produces ten thousand failures instead of one banner, a crash that loses the cursor. Each is prevented by a structural choice rather than by care: the cursor is rows in the database, the control flag is a column re-read between files, and the job is unique per session.

Output: the symlink-safe inbox scan, the staged preview, the durable session record, the session worker with cooperative control, hybrid reconcile, bounded progress with throttled journal checkpoints, the sessions console, and the receipts API.
</objective>

Create `Playstead.Import.SessionWorker` following RESEARCH Pattern 3 and the decision record's shape: one job per session, unique on the session identifier, on a dedicated import queue configured with concurrency one. Per-file job fan-out is explicitly rejected — the open-source engine has no global concurrency control, so a fan-out design would have to pause thousands of individual jobs to pause one user's session. The worker's durable cursor is the pending source-file rows themselves, iterated in the deterministic order task 1 established; nothing about where the session is lives in worker memory, so a crash costs one file rather than a session.

Before each file the worker re-reads the control decision from the session row. This is the whole pause mechanism, and it is deliberately not the framework's own queue pause: that control is global and runtime-only, so using it would pause every other user's session and every export sharing the queue. Pausing lets the file in flight finish and then stops, leaving the remaining rows pending and the session marked paused. Resume and retry re-enqueue the same unique job. Retry re-queues only rows whose last attempt failed, bounded to three attempts each; bounded retries happen before a receipt is finalized, so only exhausted retries produce something a human is asked about.

Cancel marks the remaining rows skipped and keeps every copy already made. The confirmation must say exactly that, because the alternative — undoing what a session added — is a trap: a session that deduplicated against blobs it did not create cannot safely remove them, and the product promise is that library content is never silently removed. Per-item exclusion is the reversal path, and it lives in plan 02-06.

Hash with bounded concurrency across files using the configured concurrency value, defaulting to two. The distinction that matters is across which axis: concurrency is across files in the session, each task owning its own private hash accumulator threaded sequentially through that one file's chunks. RESEARCH Pitfall 1 describes what happens otherwise — a hash context cannot be split across workers, so a chunk-parallel design produces a wrong digest that surfaces only at the read-back check, or ships silently wrong when verification has been disabled.

React to disk exhaustion at the session level, not the file level. The store's per-write preflight already refuses a file that will not fit; when that happens the worker pauses the entire session and records that file as safely failed with the disk-full reason. Continuing would turn one recoverable condition into thousands of failure receipts, which is the difference between one banner a user can act on and a wall of noise.

Implement the hybrid reconcile: on a re-scan, a source-file row whose origin, relative path, byte size, and modification time all match an existing row that reached a terminal outcome is reported as unchanged and skipped without re-hashing; anything differing in any of the four is re-hashed. Blob identity is always the full digest — the fingerprint decides only whether to spend the read. Add an explicit full-verification mode that ignores fingerprints and re-hashes everything, and keep export-then-reimport always re-hashing every byte.

Write the worker tests in the job framework's manual testing mode: pause mid-session and assert the file in flight completed and the rest are pending; resume and assert continuation from the first pending row; enqueue twice and assert one running job; fail two files and assert retry re-queues exactly those two and stops at the attempt limit; cancel and assert completed copies survive and the remainder are skipped; simulate a disk-full error and assert the session pauses with one disk-full receipt; simulate a crash mid-file and assert the session resumes with that file pending and no partial blob. Write the reconcile tests separately, including the unchanged case, each of the four fingerprint fields differing, the forced full verification, and the twice-staged idempotency case asserting zero new blobs and no duplicate logical records.
