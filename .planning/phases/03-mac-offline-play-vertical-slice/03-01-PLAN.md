Build a minimal SwiftUI macOS app target named `SpikeHost` with bundle identifier `dev.playstead.spikehost`, deployment target macOS 14.0, and `SpikeHost.entitlements` containing `com.apple.security.app-sandbox = false` and `com.apple.security.cs.disable-library-validation = false`. Per D-04 the build uses Developer ID Application signing with the hardened runtime enabled and no App Sandbox — the sandbox is what would prevent probe 2 from ever succeeding, because a sandboxed parent's child processes inherit the sandbox.

`scripts/acquire-emulator.sh` takes a candidate name and version, downloads the official upstream release archive with `curl -L` (never `--insecure`, never a mirror), prints the computed `shasum -a 256`, expands it into `~/Library/Application Support/Playstead/emulators/<name>/<version>/`, and prints `xattr -p com.apple.quarantine` on the expanded `.app` to prove the quarantine attribute is present and untouched. It must not call `xattr -d`, `xattr -c`, or `spctl --add`. Per D-02 the first candidate is mGBA standalone for GBA; the script takes the candidate as an argument so ladder rungs 2-4 (RetroArch + mGBA core, SameBoy/Gambatte, RetroArch + SNES core) reuse it unchanged.

`KeychainProbe.swift` exposes `store(account:secret:)` and `read(account:)` over `SecItemAdd`/`SecItemCopyMatching` with `kSecClassGenericPassword` and service `dev.playstead.spikehost`, returning the `OSStatus` verbatim so a hardened-runtime keychain denial is distinguishable from a not-found result. This is probe 6 and it validates the same Keychain path P1 D-07 uses for the pairing credential.

`AdapterProbeHost.swift` wraps Foundation `Process`: `launch(executableURL:arguments:environment:)`, a `terminationHandler` that records `terminationStatus` and `terminationReason` with a wall-clock timestamp into a JSONL log at `spike/out/exit-events.jsonl`, and `terminate()`/`forceKill()` helpers. Do not commit to any specific emulator CLI flag here — arguments are supplied by the probe scripts so task 2 can discover the real flag surface.

`scripts/sign-and-notarize.sh` runs `xcodebuild -scheme SpikeHost -configuration Release archive`, exports with Developer ID, runs `codesign --force --options runtime --timestamp --sign "$PLAYSTEAD_DEV_ID_APP"`, submits with `xcrun notarytool submit --keychain-profile "$PLAYSTEAD_NOTARY_PROFILE" --wait`, staples with `xcrun stapler staple`, and finally asserts acceptance with `spctl --assess --type execute --verbose`. The script fails loudly (non-zero exit) on any step rather than continuing.

Record `sw_vers -productVersion` and `sw_vers -buildVersion` into `spike/out/environment.json` at the start of every run — D-01 requires the exact macOS build in the report and Gatekeeper policy is known to tighten across releases.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream release host → local disk | A third-party emulator binary crosses from the public internet into an app-managed directory and is later executed |
| operator filesystem → SpikeHost | An operator-supplied BIOS file is read and hashed |
| emulator process → SpikeHost | A separately-signed external process reports exit status the host trusts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `acquire-emulator.sh` emulator download | high | mitigate | HTTPS-only `curl -L` from the official upstream release URL, SHA-256 printed and pinned into `03-ADAPTER-PIN.json`; quarantine attribute left intact so Gatekeeper and notarization remain the OS-level integrity gate |
| T-03-02 | Elevation of Privilege | quarantine / Gatekeeper bypass | high | mitigate | Scripts contain no `xattr -d`, `xattr -c`, or `spctl --add`; an acceptance criterion greps for these forms, and an "Open Anyway" requirement is a recorded probe FAIL rather than a workaround |
| T-03-03 | Information Disclosure | operator-supplied BIOS handling | medium | mitigate | The BIOS file is opened read-only for length and digest computation, is never copied into the repository, and only its byte length and SHA-256 appear in evidence files |
</threat_model>
