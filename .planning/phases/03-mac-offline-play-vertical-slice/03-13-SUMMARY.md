**Gate:** `blocking` (not `blocking-human`). Config `.planning/config.json` sets `"mode": "yolo"`. Per checkpoint auto-mode semantics (checkpoints.md rule 5), a `blocking` `checkpoint:decision` auto-selects the plan's stated recommendation rather than halting, since `workflow.auto_advance`/`_auto_chain_active` combined with the project's `yolo` mode indicate an unattended run, and the plan explicitly wrote Tasks 2/3 against its recommended option.

**Decision 1 answer (verbatim, auto-selected):** `ui-spec-set-any-device` — the UI-SPEC's six values (`needs_attention`, `missing_dependency`, `downloading`, `ready_offline`, `queued`, `server_only`; pinned/verified merged, `safe_to_evict` excluded per D-13), fed by per-device reports merged across ANY of the user's paired devices.

**Decision 2 answer (verbatim, auto-selected):** a new device-authenticated endpoint `PUT /api/v1/devices/me/availability` under the existing `cache` capability namespace, a per-device `device_asset_availability` table, and an any-device merge at read time (boolean OR per fact, `download_percent` maximum).

No `playstead-server/` or `shared/` files were modified before this decision was recorded (verified: `git status --porcelain -- playstead-server shared` was empty at Task 1's start).

## Accomplishments

- Device-reported availability facts (`Playstead.Availability.replace_for_device/2`, full per-device replacement inside one `Ecto.Multi` transaction) merge per user at read time (`facts_for_user/1`) with no stored ladder rank (D-21).
- `Playstead.AvailabilityVocabulary` is the frozen, six-value console filter vocabulary, mirrored by `shared/availability-vocabulary.json` and proven never to drift via an exhaustive, both-directions contract test.
- `PUT /api/v1/devices/me/availability` follows `PlaySessionsController`'s `Idempotency.execute/4` shape exactly; the `cache` capability namespace advertises `1.1.0` additively (transfer-1.1.0 precedent), never renaming or removing anything.
- `matches_availability?/3` in `LibraryLive` now has one clause per vocabulary value comparing `StatusSlot.describe/2`'s rank — the unconditional pass-through clause that caused the LIBR-02 gap is gone. `handle_event("filter-availability", ...)` validates against the vocabulary before touching any assign; no client-supplied value is ever converted to an atom.
- The six chips are generated by iterating `AvailabilityVocabulary.values/0`, each carrying `aria-pressed`, an `aria-label` from `accessible_name/1`, and a 44×44 minimum-target class (`min-h-11 min-w-11`) — the two pre-existing chips had neither.
- The filtered-to-zero blank-pane defect is fixed: an explanatory empty state now renders whenever search text, a system chip, or an availability chip narrows the set to zero results, with one `clear-narrowing` control back to the unfiltered library.
