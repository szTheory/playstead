<objective>
Deliver LIBR-05 console parity per D-11: the responsive LiveView console browses the same canonical library, curates all five nouns through the same context functions the API uses, finds content by search, system, and availability, hides empty and irrelevant surfaces by default, and meets the accessibility floor QUAL-01 sets for the web half.

</objective>

Create `PlaysteadWeb.LibraryLive.StatusSlot` as the one place the status vocabulary is expressed. It renders exactly one indicator, chosen by the ladder in which needs-attention outranks a missing dependency, which outranks an in-progress download, which outranks queued, which outranks verified or pinned, which outranks server-only. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated browser → LiveView events | User-supplied search text, filter values, collection names, and reorder neighbour ids cross into context calls |
| catalogue data → rendered markup | Imported filenames and derived titles, which originate from untrusted user files, are rendered |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-15 | Elevation of Privilege | LiveView curation events | high | mitigate | Every handler passes `socket.assigns.current_scope` into the `Playstead.Curation` function rather than trusting any id in the event payload as authorization; the context's own user filter is the enforcement point and is not re-implemented here |
| T-03-16 | Information Disclosure | rendering of imported filenames and titles | medium | mitigate | All display text renders through HEEx interpolation, which escapes by default; no raw markup helper is used on catalogue-derived or user-entered strings; collection names pass the existing title sanitizer before storage |
</threat_model>
