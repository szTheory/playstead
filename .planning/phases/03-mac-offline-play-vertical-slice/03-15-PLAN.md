<objective>
Make `missing_dependency` a real signal instead of a constant.

`03-14` shipped `AvailabilityReporter` with `missingDependency` hardcoded on every entry it builds, for every game, unconditionally. It is the only writer of `device_asset_availability.missing_dependency` in the codebase, so the chip `03-13` built can never return a non-empty result for any real user — the original pass-through defect, inverted from always-everything to always-empty. The independent re-verification caught this and rejected the LIBR-02 closure.

The owner decision is already made and is not re-opened here: implement the real signal. The operative definition is `03-VERIFICATION.md`'s own words — *a required member that the catalogue manifest names but that is absent locally and is neither currently downloading nor queued*.

Task 1 computes that fact from the three stores `buildEntries` already holds, and proves it with tests that drive `buildEntries` from real catalogue/CAS/queue/pin state. Task 2 closes the transport hole that let the previous round look green: one committed fixture carries the exact body the Swift encoder produces, the Elixir test PUTs that body to the real endpoint, and only then asserts the chip returns the game. A test that seeds the read model is explicitly not accepted as the proof.

Purpose: make the sixth availability value reachable in production, and prove it along the path a real device actually takes.
Output: a computed `missingDependency` fact, a two-sided report fixture, an HTTP-driven console assertion, and harness registration for the new suites.

**Scope fence.** This plan does not touch the four environment-blocked items `03-VERIFICATION.md` records (physical controller hardware, a live interactive emulator session, the experiential VoiceOver walkthrough, acceptance of real BIOS bytes). It flips no requirement checkbox and edits no verification verdict — `03-16-PLAN.md` does that, gated on this plan's own observed test runs.
</objective>

<planner_assumptions>
1. **FLAGGED — the literal definition needs one guard, and an already-green required test proves it.** Read literally, *"a required member that is absent locally and is neither downloading nor queued"* is true of every never-downloaded game, because all of its required members are absent and none are queued. That would make `missing_dependency` outrank `server_only` on `StatusSlot`'s frozen ladder for every untouched game, leaving the `server_only` chip structurally dead — the identical defect, moved one slot down. This is not a judgment call: `AvailabilityReporterTests.test_noLocalBytesAndNoQueueRow_emitsAllFactsFalseNeverOmitted` already asserts `missingDependency` is false for exactly that state, and that test is in `run-mac-verification.sh`'s required list, so the literal reading contradicts a currently-passing required test. The predicate therefore carries an *engagement* guard: the fact is only claimed for a game the device has actually started holding (at least one required member cached, or pinned, or at least one required member with a live queue row). Rated reversible — it is one conjunct in one predicate, and every existing required test constrains it. Surfaced here rather than decided silently.
2. **FLAGGED — probe row LIBR-02 is `unclassified`/`unresolved` and stays that way.** The deterministic edge probe was run against LIBR-02 only, because in gap-closure mode the contracted requirement set is the unresolved set from `03-VERIFICATION.md`, not the phase's fourteen already-closed IDs. 3. **"Queued" includes paused, and excludes cancelled.** `AvailabilityInputs`' own doc comment already fixes this: a member is in the queue in any of `waiting`, `active`, `paused`, and a `cancelled` row is not in the queue. The new predicate reuses that exact definition rather than inventing a second one, so the client never carries two disagreeing notions of "queued".

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mac client local stores -> outbound report | The client asserts, to a server, facts about content it holds; the report crosses the device boundary |
| device HTTP request -> `Playstead.Availability` | An attacker-controllable body from a compromised or buggy device client reaches an Ecto write path |
| device-reported facts -> console rendering | Facts one device asserts are merged per user and shown to that user as readiness state |
| report producer -> launch path | A background network producer shares a process with the offline launch guarantee |
