    - The test view reflects each button and axis as it is pressed or moved.
    - A mapping assigns each adapter input to a controller input and persists across a restart.
    - Resetting restores the default mapping and persists that too.
    - Disconnecting publishes a disconnected state and shows a recovery affordance without modal interruption.

    - Reconnecting restores controller input with no relaunch and dismisses the recovery affordance.

  <action>
`ControllerHost` wraps the Game Controller framework's connect and disconnect notifications and its current-controller list, publishing a `ControllerConnectionState`. Register for the notifications at application launch rather than when a settings view appears, so a controller connected before the window opens is already known.

`ControllerMapping` maps each adapter input named by the pin's configuration keys to a controller input. `ControllerMappingStore` persists it in `controller_mappings` keyed by the controller's product identifier, so a user's mapping follows their controller. `AdapterHost` injects the active mapping through the pin's configuration mechanism at launch; a mapping the emulator never reads would look correct in settings and do nothing in the game, so a test asserts the injected configuration contains the mapped values.

`ControllerTestView` shows every button and axis live so a user can confirm a mapping by pressing rather than by trusting a label. `ControllerSettingsView` offers assign, per-input remap, and reset to defaults.

On disconnect, publish the state and show a quiet, non-modal recovery affordance naming the controller and what to do. Do not block, do not open a modal, and do not pause anything the user did not ask to pause. Every surface remains fully operable by keyboard and by pointer throughout: a user whose controller battery dies mid-navigation must never be trapped in a state they cannot leave, and that property is what makes the controller an enhancement rather than a dependency.

Directional-pad navigation moves within a shelf and between the sidebar's focus sections; shoulder buttons cycle sidebar sections; the menu button opens the contextual sheet for the focused item.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operating system input devices → application | Controller input crosses into navigation and into injected adapter configuration |
| build pipeline → distributed bundle | Signing and notarization credentials produce the artifact users execute |
| application → adapter child process | A child process is spawned and must be supervised through the application's lifetime |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-28 | Tampering | release signing and notarization | high | mitigate | Hardened runtime, secure timestamp, Developer ID signing, notary submission, stapled ticket, and a scripted Gatekeeper assertion that fails the build if the bundle is not accepted; no nested third-party code is bundled |
| T-03-29 | Denial of Service | orphaned adapter process | medium | mitigate | Every launched process is registered and terminated on application termination, so a quit cannot leave an emulator holding the save file open and blocking the next launch |
</threat_model>
