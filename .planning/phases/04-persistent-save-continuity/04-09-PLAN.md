<objective>
Make save state honestly visible: three orthogonal axes rather than one ladder, a game-level rollup that never says "backed up", a navigational Save row, a session-grouped history sheet, and one shared vocabulary both runtimes assert against.

Purpose: SAVE-02 asks that a user can see whether a revision is local-only, queued, uploaded, current, restored, or in conflict without a generic "synced" label hiding the distinction. The apparent collision with the shipped single status slot is a category error — the card is a router, not an explainer — and dissolving it that way is what lets the phase add a surface without rebaselining a single snapshot.

Output: `shared/save-vocabulary.json`, a three-axis state model, the rollup, the readiness Save row, the per-game history sheet, and exhaustiveness-asserting copy tests on both sides.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored save state → user-facing claim | A label is a promise about where irreplaceable bytes are |
| two runtimes → one vocabulary | SwiftUI and HEEx can drift apart silently |
| device names and titles → row identity | Untrusted display strings could be used to group rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09-01 | Spoofing | a label claiming durability the bytes do not have | high | mitigate | "Backed up" is banned from every save surface and the destination is always "your server"; the rollup reads the newest revision's durability from the committed local store, never an in-flight state |
| T-04-09-02 | Repudiation | copy drift between the Mac and the console | medium | mitigate | One shared vocabulary artifact read as a test resource on both sides, with exhaustiveness asserted in both directions so an unlisted string fails |
| T-04-09-03 | Tampering | row grouping driven by attacker-influencable display names | medium | mitigate | Rows are keyed by stored revision identity and digest, never by device-name or title string comparison |
| T-04-09-04 | Information Disclosure | digests, paths, or internal nouns leaking into player copy | medium | mitigate | The banned-word scan over vocabulary values covers sha256, digest, hash, journal, blob, CAS, and the rest; those remain available only behind the per-row "Details" disclosure for support |
| T-04-09-05 | Denial of Service | hashing during render on a large history | low | mitigate | Durability is read from SQLite and never hashed at render; the timeline is session-grouped rather than flat |
| T-04-09-06 | Elevation of Privilege | the Save row blocking launch | medium | mitigate | The Save row cannot produce `.blocked` and does not contribute to the blocker count, asserted by test for every input including two divergent heads |
| T-04-09-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install occurs in this plan; RESEARCH.md's Package Legitimacy Audit records that this phase installs no external packages |
