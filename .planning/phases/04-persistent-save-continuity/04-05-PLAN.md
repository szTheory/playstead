<objective>
Complete the revision DAG: parent pointers, recorded base evidence, accept-and-branch commits, derived branch heads, the commit invariants that keep the history honest, and append-only divergence resolution.

Purpose: SAVE-04 asks that when two devices create revisions from the same base, both are retained and the user can resolve without silent last-write-wins. The DAG is what makes that structurally true rather than policy-true. Because a 32 KB battery save is opaque and unmergeable, the DAG never merges — it exists for causality and provenance.

Output: The full lineage model, a branch-head derivation module, a read-only history endpoint, and the resolution commit path both clients append through.
</objective>

Add `Saves.resolve_divergence/4` and `Saves.acknowledge_divergence/3` to the context, and expose them through `SavesController` as idempotent commits under `:device_auth` + `:idempotency`, following the same `run_idempotent` shape as the revision commit.

Resolution appends rather than mutates: insert one new revision whose bytes are the chosen side's (resolved through the CAS by digest, so it adds zero new blob bytes), and insert one `save_revision_parents` row per divergent head — exactly one with role `chosen`, every other with role `acknowledged`. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device-claimed parent pointer → server lineage | A client asserts what its revision descends from |
| device-claimed clock → displayed time | Device times are evidence, server `recorded_at` is truth |
| one user's lines → another user's reads | History and resolution endpoints are user-scoped |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05-01 | Repudiation | silent data loss via non-fast-forward rejection | high | mitigate | Accept-and-branch: a rejected commit would leave the losing side's only durable copy on a client, inverting the project's first priority; the only 409 is `save_parent_unknown`, which is retried, not surfaced |
| T-04-05-02 | Tampering | mutation of a committed revision | high | mitigate | `save_revision_immutable` (409) on any modification attempt; resolution appends a new revision and never rewrites a head |
| T-04-05-03 | Elevation of Privilege | cross-user save line access | high | mitigate | Every query is `user_id`-scoped; an out-of-scope line returns 404 rather than 403, so existence is not confirmed |
| T-04-05-04 | Denial of Service | unbounded branch fan-out on one line | medium | mitigate | `save_branch_limit_exceeded` at 32 heads, raised loudly rather than silently dropping a commit |
