<objective>
Connect the launch-path save restore built in plan 04-07 to the Play button, so that the capability the phase promises is reachable by a user rather than only by a test harness.

Purpose: `LaunchSavePlanner` and `SavePlanExecutor` are implemented, tested, and proven byte-identical through `SaveRestoreProofTests` — but `GameRowView.play()` calls `adapterHost.launch(...)` without passing `executeSavePlan`, so the default `nil` applies and no plan runs on the real Play path. The phase's headline capability is currently unreachable outside `UITestBootstrap`.

Output: A production `SavePlanExecutorEnvironment` backed by the real CAS and `SaveStore`, a context builder that assembles `LaunchSaveContext` from already-local facts, and a wired Play path with a test that fails if the wiring is ever removed.
</objective>

    - `revisionBytes(forDigest:)` returns the bytes for a digest present in the CAS.
    - `revisionBytes(forDigest:)` throws rather than performing any network call when the digest is absent from the CAS.
    - `captureExistingFile(at:)` records the pre-existing on-disk artifact before it is overwritten, so a restore can never be the only copy's last moment.

  </behavior>
  <action>
Add `LaunchSaveEnvironment.swift`: a `SavePlanExecutorEnvironment` conformance backed by `CASManager` and `SaveStore`. `revisionBytes(forDigest:)` resolves through `CASManager.objectURL(for:)` and reads the file; when `CASManager.contains(_:)` is false it throws — it must never reach for the network, because the launch path is forbidden from fetching bytes it does not already hold (D-43/D-F03). Route `quarantineCorruptRevision` to the CAS quarantine path rather than any delete.

Add `LaunchSaveContextBuilder.swift`: given an asset set id and the resolved save directory, assemble a `LaunchSaveContext` from already-local facts only. Resolve the save line, read its heads via `SaveStore.fetchHeads(saveLineID:)`, mark each head's `bytesLocal` from `CASManager.contains(_:)`, hash the on-disk artifact for `onDiskDigest` (treating missing and zero-byte alike as `nil`), populate `knownDigests` from the line's recorded revisions, and attach a compatibility verdict only when there is exactly one head to evaluate.

When no save line exists, return a context that yields a no-op plan — a first-ever launch of a game is the normal case, not an error.

Both types are plain and injectable; neither performs I/O in an initializer.
  </action>
