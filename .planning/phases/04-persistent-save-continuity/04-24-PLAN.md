<objective>
Give revision ordering a stable secondary sort key so an export's `seq` — and therefore every exported filename — is the same on every run, including when two revisions share a `recorded_at` to the microsecond.

Purpose: 04-VERIFICATION scores this phase 4/5. The one failing criterion is ROADMAP criterion 4 / PORT-01, and it fails on a single word: "deterministic". `Saves.get_history/2` (saves.ex:411) and `Branches.heads/2` (branches.ex:45) both order by `recorded_at` alone. Postgres guarantees nothing about tied values across two executions, so a re-export can assign a different `seq` — and therefore a different filename — to a revision already shipped to a self-hoster. The manifest still hashes correctly and `Verifier.verify/1` still reports success, so nothing detects the silent rename. This falsifies D-59 and 04-21's own must-have truth #5.

Output: a total order on both queries, an input-order-independent sort inside `SavesPlan.plan/2`, and a regression test that constructs a real microsecond tie and proves the exported filenames survive two independent export runs — a test that is demonstrated RED against the current code before it is allowed to be green.
</objective>
