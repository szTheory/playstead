Output: A capture subsystem that is correct across session end, app death, full disks, and eviction.
</objective>

  <behavior>
    - A session with five quiescent changes produces five successive staged captures, each superseding the last, and exactly one promoted revision at session end.
    - The promoted revision's parent is the session's baseline revision when one was created, and the line's prior head otherwise.
    - Opening a session when the on-disk bytes differ from the last recorded revision creates a baseline revision marked `origin: external` before any staged capture.
    - Opening a session when the on-disk bytes match the last recorded revision creates no baseline revision.
    - `SaveArtifactSet` produces a sorted, timestamp-free manifest of `(path, size, sha256)` entries; two runs over the same files produce byte-identical manifests.
    - The revision's stored blob digest equals the raw artifact's sha256 and, for the single-entry mGBA case, is not equal to the manifest digest.
    - A zero-byte artifact does not produce a revision.
  </behavior>
  <action>
Add `SaveArtifactSet.swift` defining the capture unit: a value type holding a sorted, timestamp-free list of `(path, size, sha256)` entries plus a derived `manifestDigest`. Sorting is by path, and no wall-clock value participates, so the manifest is a stable function of the bytes. mGBA yields exactly one entry today; the type exists so a directory-shaped or multi-file save (memory cards, an `.srm` plus an `.rtc`) slots in later without a schema migration. This is the only abstraction in the phase built ahead of need.

The stored blob digest is the raw artifact sha256. Record `manifestDigest` alongside it in the local row and in the payload, but never key dedupe, export filenames, or the compatibility gate off it — those three must agree with what a user sees from `sha256sum` on the file.

Extend `SaveCapturePoller` to D-04's two tiers. A staged capture is durable and rolling: each quiescent change is written through D-06's order (one buffer, one digest, temp, `fsync`, `rename`, `fsync` directory, then the row) and supersedes the previous staged capture for that session. Exactly one revision is promoted per session, at session end after the unconditional settle pass. At session start, compare the on-disk artifact's digest to the last recorded revision for that line; when they differ, create a baseline revision with `origin: external` first, so the session's promoted revision has an honest parent and the out-of-band change is not silently absorbed.

Add the local columns these need in `Migrations.swift` (forward-only): the staged/promoted/baseline tier discriminator, `origin`, `manifest_digest`, `session_id`, and the artifact-set manifest itself stored as JSON.

Write `SaveCaptureTierTests.swift` covering the seven behaviours above, driving the poller with the injected clock and byte-source established in plan 04-04.

    - Replay when nothing changed since the last recorded revision produces no revision and no user-visible output.
    - Running recovery twice produces exactly one promoted revision for that session.
    - Running recovery concurrently with a live poller for the same session produces exactly one promoted revision.

  <action>
Add `SaveSessionRecovery.swift`. At app launch it enumerates sessions left open in `SaveStore` and replays the identical settle pass the poller runs at session end — the same code path, not a reimplementation. It is idempotent by digest: a replay that computes a digest already recorded for that session promotes nothing and produces no user-visible output. Guard the promote step so a recovery running alongside a live poller for the same session cannot double-promote; the session's promotion is a single-winner operation. Do not branch any part of recovery on `AdapterExit`; a session with no recorded exit is replayed exactly like one with a clean exit.

Add `SaveCaptureBlockedState.swift` implementing D-31's named, loud-once, never-silent failure. On a disk-full (or any write-refusal) error during capture: write a durable blocked row recording the line, session, digest, and reason; raise exactly one alert per distinct blockage; hold a persistent attention state until the blockage clears; retry on every subsequent poll cycle; and offer a direct-upload escape hatch that streams the staged bytes to the server without first landing a local blob. Delete nothing, and never stop or interrupt the running game — the emulator keeps running and keeps writing, and Playstead keeps trying.

The attention state is raised through the saves-owned source; it must not be expressed as a `Playstead.Attention.Reason` member.

Write `SaveSessionRecoveryTests.swift` covering the nine behaviours above, simulating disk-full by injecting the write failure rather than filling a real volume.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| emulator writes ↔ Playstead reads | A live mmap writer mutates the artifact while capture reads it |
| app death ↔ durable state | A crash can land between the blob write and the row insert |
| quota policy → save bytes | The eviction path decides what may be deleted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06-01 | Tampering | torn read of a live mmap artifact | high | mitigate | Raw SRAM is not self-describing, so temporal quiescence is the only available detector: three consecutive identical 1 Hz reads before any capture, and the bytes are never parsed |
| T-04-06-02 | Denial of Service | save loss on disk-full | high | mitigate | D-31's durable blocked row, one alert, persistent attention, retry every cycle, and a direct-upload escape hatch; nothing is deleted and the game keeps running |
| T-04-06-03 | Repudiation | lost promotion when the app dies after emulator exit | high | mitigate | `SaveSessionRecovery` replays the identical settle pass at launch, idempotent by digest, single-winner promotion |
| T-04-06-04 | Denial of Service | eviction reclaiming irreplaceable save bytes | high | mitigate | Save revisions are unconditionally excluded from eviction candidate selection, asserted by test at maximum quota pressure |
| T-04-06-05 | Tampering | out-of-band edits to the artifact absorbed silently | medium | mitigate | A session-start baseline revision marked `origin: external` records the out-of-band change as its own node rather than folding it into the session's promotion |
| T-04-06-06 | Information Disclosure | blocked-capture alert content | low | mitigate | The blocked row records the line, session, digest, and reason internally; the user-facing alert carries no path, ROM name, or digest, per QUAL-03 |
| T-04-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install occurs in this plan; RESEARCH.md's Package Legitimacy Audit records that this phase installs no external packages |
