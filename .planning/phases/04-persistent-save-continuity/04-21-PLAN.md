`SavesLineage.branch_keys/1` takes a list of `%{id:, parent_revision_id:, recorded_at:}` maps and returns a `%{revision_id => branch_key | nil}` map. The derivation, which satisfies D-58's stability requirement without ever touching a device name:
- Build the child-count map from `parent_revision_id`.
- A revision's **fork root** is the nearest ancestor-or-self whose own parent has more than one child, found by walking `parent_revision_id` upward. A revision with no such ancestor is on shared, pre-fork history and its `branch_key` is `nil`.
- The `branch_key` is that fork root's `id` string — a fixed, immutable UUID, so it is stable across two planning runs and inherited by every descendant of the fork, which is precisely what makes `SavesPlan.assign_branch_letters/1` assign the same letter to the same side forever.
- Guard against a cycle: cap the upward walk at the number of revisions and return `nil` rather than looping.

Map the kind at the boundary in `Export.load_save_revisions/2`: a line whose `save_kind` is `"battery"` is the system save this product ships, so pass `save_kind: "system_save"` in the revision input.
