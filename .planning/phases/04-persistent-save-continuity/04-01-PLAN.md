  <action>
Build a self-contained probe with two pieces, both under `playstead-mac/scripts/probes/`.

`save-p1-probe.swift` is a single-file Swift script (run via `swift save-p1-probe.swift`, no Xcode target, no new package dependency) that creates its own temporary directory under `NSTemporaryDirectory()`, and inside it runs one full measurement pass over a 32,768-byte artifact named `probe.sav` — the exact size of a GBA `sram_32k` artifact — then removes the directory. The pass has four measurement stages, each writing one entry into a `measurements` object keyed `inode_stability`, `mtime_fidelity`, `event_delivery`, `post_death_writeback`:

1. `inode_stability` — open `probe.sav`, `mmap` it `MAP_SHARED`, mutate bytes, `msync`, and record `st_ino` and `st_dev` from `fstat` before the first mutation and after each of at least five mutation+`msync` rounds. Report `stable: true` only when every observed `(st_dev, st_ino)` pair is identical, and include the observed pairs.

2. `mtime_fidelity` — for each of the same rounds, record `st_mtimespec` (full nanosecond resolution) alongside the SHA-256 of the whole 32 KB buffer read back through a fresh `read(2)`. Report `mtime_advanced_on_every_content_change` (did mtime strictly increase whenever the digest changed), `content_changed_without_mtime_advance_count`, and `mtime_advanced_without_content_change_count`. This is the measurement that decides whether the widely repeated mtime heuristics are usable — it does not change D-01, which does not use them.

3. `event_delivery` — register both an `FSEventStreamCreate` stream on the temp directory and a `DispatchSource.makeFileSystemObjectSource` vnode source (`.write`, `.extend`, `.attrib`) on the open descriptor, then perform the same mutation rounds through the `MAP_SHARED` mapping with no `write(2)` call at all. Record `fsevents_events_received`, `vnode_events_received`, and per-round `event_observed_within_ms` with a bounded wait (2000 ms per round). This directly measures the "FSEvents misses mmap writes" claim that D-01 notes is documented for inotify/fanotify and unmeasured for FSEvents.

4. `post_death_writeback` — fork a child (or spawn the same script with a `--writer-child` flag) that maps the file `MAP_SHARED`, mutates it without `msync`, and is then killed with `SIGKILL` from the parent. The parent then polls the file's digest for up to 10 s and records `digest_changed_after_process_death` and `observed_delay_ms`. This is the measurement behind D-05's rule that the post-exit settle pass must be unconditional.

Emit one JSON object on stdout with top-level keys `probe_id` (the literal `SAVE-P1`), `run_id` (a UUID), `recorded_at` (ISO-8601 UTC), `environment` (`os_version`, `hardware_model`, `filesystem_type` read from `statfs` on the temp dir — assert it is `apfs` and record it either way, `page_size`, `artifact_bytes: 32768`), `mgba_observed` (see below), `measurements`, and `conclusions` (a list of short prose findings). Exit non-zero if any stage throws; a stage that completes but observes nothing records its zero counts and still exits zero — an observed absence is a measurement, not an error.

`mgba_observed` defaults to `false`. Accept an optional `--mgba-artifact <path>` argument: when supplied, the probe additionally runs the `inode_stability` and `mtime_fidelity` stages as a read-only observer against that live artifact instead of its own writer, and sets `mgba_observed: true`. When the flag is absent the probe runs entirely on its synthetic writer and honestly reports `false` — the real-emulator confirmation is carried by CP7-SAVE-C in plan 04-12, never inferred here.

`run-save-p1-probe.sh` is a thin POSIX wrapper: it runs the Swift script, writes stdout to `.planning/phases/04-persistent-save-continuity/04-SAVE-P1-REPORT.json`, and passes any arguments through. Follow `playstead-mac/scripts/ci/run-mac-verification.sh`'s conventions for `set -euo pipefail`, `SCRIPT_DIR` resolution, and `die()`-style failure messages; do not add the probe to any `.xctestplan`.

The probe writes only inside its own temporary directory. It must never read from, write to, or create anything under the Playstead Application Support root, and must never open a real `.sav` for writing — the optional `--mgba-artifact` path is opened read-only.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| probe process → local filesystem | The probe creates, maps, and deletes files; a mis-scoped path would touch real user data |
| probe child process → parent | The `post_death_writeback` stage deliberately `SIGKILL`s a child; an unbounded child could outlive the run |
| report artifact → downstream plans | Later plans and CP7-SAVE-C cite this report as evidence; a fabricated or truncated report would launder an inference as a measurement |
