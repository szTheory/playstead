## Decisions Made

- **https promoted, not added alongside** — the assumption-delta decision recorded in the plan: the plaintext listener is gone, not kept as a fallback, so no live-server consumer can keep proving itself over plaintext.
- **CA last in the chain** — `server.pem`'s final certificate is the CA (not the leaf), because `PinnedCertificateCapture` pins `SecTrustCopyCertificateChain(...).last`; a leaf-last chain would have pinned the wrong certificate for the relaunch path.
- **WR-01 is a compile-time gate, not a runtime flag** — because the XCUITest target itself runs the Debug configuration, a runtime check could not distinguish "test wants the override" from "hostile environment variable wants the override" in Release; only `#if DEBUG` can.
- **The SaveEndToEndTests failure was root-caused and filed, not silently dropped** — an A/B against the pre-TLS commit (`bfc9778`) proved the failure predates this plan and is transport-independent, so it was filed as a scoped todo with the mechanism, the A/B table, and candidate fixes rather than left as an unexplained red must-have.

### Unmet Must-Have (recorded honestly, not silently passed)

**The rest of the live-server layer still passes over https — LiveServerSnapshotTests, SaveEndToEndTests, and SaveRestoreProofTests are green against the same TLS endpoint.**

- **Status: PARTIALLY MET.** `LiveServerSnapshotTests` and `SaveRestoreProofTests` are green over https. `SaveEndToEndTests` is **red** — `testOneSaveRoundTripsCaptureUploadAndJournalReturn` fails with `save-e2e-harness=upload-did-not-complete` at `SaveEndToEndTests.swift:167`.
- **Root cause (not merely observed, traced):** two `POST /api/v1/saves/revisions` requests land within the same millisecond; the first gets `201`, the second `409`; the 409 makes `SaveUploadLane.uploadAndCommit` throw, `drainOnce` takes its `stoppedForRetry` path and returns `sent = 0`, and `UITestBootstrap.swift:272` requires exactly `sent == 1`. The second concurrent writer's origin is unconfirmed — hypothesized to be a previous test class's app instance still draining against the same shared Phoenix — but that hypothesis is not yet verified.
- **Proven NOT caused by this plan's TLS move, by A/B:**

  | Tree | Transport | Ceremony test | SaveEndToEndTests |
  |---|---|---|---|
  | `bfc9778` (pre-04.5-04) | plaintext http | failed (expected — https-only refusal) | failed — same line 167, same marker, same concurrent 201/409 pair |
  | `HEAD` (04.5-04) | https | passed | failed — identical signature |

  No TLS errors, handshake failures, or closed connections appear in either transport's `phoenix.log`. The https move neither caused nor worsened this failure.
- **Why it was never caught before:** `run-mac-verification.sh` names only `LiveServerSnapshotTests` as the live-server layer's required test; `SaveEndToEndTests` runs, fails, and is ignored, so this has been red since before this phase existed without anyone being told — the same fail-open shape 04.5-05 exists to close for the ceremony test.
- **Disposition:** deliberately deferred, not fixed here. Filed at `.planning/todos/pending/save-e2e-duplicate-revision-409.md` with the mechanism, the A/B table, and candidate fixes (isolation, idempotency, or a retrying drain). Out of scope because none of this plan's `files_modified` touch `SaveEndToEndTests.swift`, `UITestBootstrap.swift`, `SaveUploadLane.swift`, or the server's revision-creation path — it belongs to the Phase 4 save layer and needs its own plan.
