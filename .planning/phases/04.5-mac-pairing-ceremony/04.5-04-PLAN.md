- **A-01 (unresolved edge — concurrency, PROT-01).** "If interrupted or run in
  parallel, what is guaranteed?" is *unresolved* for this phase: no SPEC.md
  exists and the edge-coverage probe could not resolve it. It is materially
  live here, because a TLS fixture adds two new interruption surfaces that did
  not exist when 04.5-03 hardened in-process cancellation: (a) a run killed
  between `mac-ci-tls.sh trust` and its `untrust` leaves a CA trusted in the
  System keychain, and (b) two live-server runs on one machine contend for port
  4010 and for `$PLAYSTEAD_MAC_CI_ROOT/tls`. This plan mitigates both
  mechanically (`issue` refuses a pre-existing `tls/` directory; `untrust` runs
  from the EXIT trap and exits non-zero on failure) but does not *prove* the
  guarantee under a real SIGKILL. Recorded as a backstop truth, not as verified.
- **A-02.** `mac-ci-tls.sh trust` needs non-interactive `sudo`. GitHub's hosted
  macOS runners provide passwordless sudo; a developer machine may prompt once.
  The script fails closed with a distinct token rather than continuing untrusted.
- **A-03.** The app pairs using platform default trust evaluation
  (`PinnedCertificateCapture` always returns `.performDefaultHandling`). That is
  why this plan makes the CI CA genuinely trusted on the machine instead of
  relaxing the app's trust path. It also means a self-hoster with an untrusted
  self-signed certificate cannot pair today. That is a **product** question
  beyond this gap-closure scope — record it in the SUMMARY as a carried item,
  do not change production trust behavior here.
</assumptions>

Create `playstead-mac/scripts/ci/mac-ci-tls.sh` (mode 0755, `set -euo pipefail`),
a run-scoped TLS issuer with four subcommands, all taking `<server_root>` (the
value of `PLAYSTEAD_MAC_CI_ROOT`) as their single argument:

- `issue <server_root>` — die if `<server_root>/tls` already exists (mirror the
  runner's existing "already exists" fail-closed style); otherwise
  `mkdir -m 0700`. Write `<server_root>/tls/openssl.cnf` with a `[req]` section
  (`distinguished_name = dn`, `prompt = no`), a `[dn]` section, a `[v3_ca]`
  section (`basicConstraints = critical,CA:TRUE`,
  `keyUsage = critical,keyCertSign,cRLSign`, `subjectKeyIdentifier = hash`), and
  a `[v3_leaf]` section (`basicConstraints = critical,CA:FALSE`,
  `keyUsage = critical,digitalSignature,keyEncipherment`,
  `extendedKeyUsage = serverAuth`, `subjectAltName = IP:127.0.0.1,DNS:localhost`,
  `subjectKeyIdentifier = hash`, `authorityKeyIdentifier = keyid,issuer`). Use an
  explicit config file rather than `-addext` so the script works on both
  Homebrew OpenSSL 3 and the system LibreSSL. Then, with `umask 077`:
  1. CA: `openssl req -x509 -newkey rsa:2048 -sha256 -days 397 -nodes
     -keyout tls/ca-key.pem -out tls/ca.pem -config tls/openssl.cnf
     -extensions v3_ca -subj "/CN=Playstead Mac CI Root $(uuidgen)"`.
  2. Leaf CSR: `openssl req -new -newkey rsa:2048 -nodes -keyout
     tls/server-key.pem -out tls/server.csr -config tls/openssl.cnf
     -subj "/CN=127.0.0.1"`.
  3. Sign: `openssl x509 -req -in tls/server.csr -CA tls/ca.pem -CAkey
     tls/ca-key.pem -CAcreateserial -days 397 -sha256 -extfile tls/openssl.cnf
     -extensions v3_leaf -out tls/server-leaf.pem`.
  4. Chain file: `cat tls/server-leaf.pem tls/ca.pem > tls/server.pem`. The CA
     MUST be last in the presented chain, because `PinnedCertificateCapture`
     pins `SecTrustCopyCertificateChain(...).last` — a leaf-only chain would pin
     the leaf and break the pinned relaunch path.
  5. DER anchor: `openssl x509 -in tls/ca.pem -outform DER -out tls/ca.der`.
  6. `chmod 0600` every file in `tls/`, then `rm -f tls/server.csr`.
- `fingerprint <server_root>` — print the CA's SHA-1 fingerprint as bare
  uppercase hex with no colons (derived from
  `openssl x509 -in tls/ca.pem -noout -fingerprint -sha1`), for
  `security delete-certificate -Z`.
- `trust <server_root>` — first `sudo -n true` or die with the exact token
  `mac-ci-tls: passwordless sudo unavailable`; then
  `sudo -n security add-trusted-cert -d -r trustRoot -p ssl -k
  /Library/Keychains/System.keychain <server_root>/tls/ca.pem`. Idempotent: a
  re-add of the same certificate must exit 0. Print `mac-ci-tls: trusted <fp>`.
- `untrust <server_root>` — `sudo -n security remove-trusted-cert -d
  <server_root>/tls/ca.pem` then `sudo -n security delete-certificate -Z <fp>
  /Library/Keychains/System.keychain`. Treat an already-absent certificate as
  success and print `mac-ci-tls: untrusted <fp>`; on any other failure print
  `mac-ci-tls: UNTRUST FAILED <fp>` and exit non-zero. Never swallow the
  failure — a leftover trusted root on a machine is the worst outcome here.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mac app → mac_ci Phoenix (loopback TLS 4010) | The pairing ceremony crosses here with a self-generated `device_code` and receives a scoped credential; it is untrusted until the TLS anchor is validated. |
| CI harness → macOS System keychain | The harness installs a trust root, mutating machine-wide trust state for the duration of a run. |
| Run-owned native root → filesystem | The CA private key lives here; anything that can read it can impersonate any server the runner trusts. |
| Test-only environment → production app binary | `PLAYSTEAD_UI_TEST_PAIRING_DEVICE_NAME` crosses this boundary today (WR-01). |
