### Gaps Summary

One new blocking gap, found by this verification pass and not previously reported: **ROADMAP criterion 5's second half is unimplemented.** `PairingCoordinator` correctly captures and writes the pairing-time trust anchor to `AppPaths.root/pinned-ca.der`, but `APIClient` — the object that makes every subsequent authenticated request — is never constructed with a `pinnedCertificateURL`, in production or in the UI-test harness. The file gets written; nothing ever reads it. This is a real security-relevant gap (trust-on-first-use pinning is inert, not merely undocumented), not a documentation or scope nit: the app's actual behavior after a successful pairing is unconditional default-trust evaluation on every request, forever. `PairingCeremonyTests`' existing `pinned-ca.der` assertion cannot catch this because the CI harness's CA is separately installed as a System-trusted root, so the test's relaunch-and-fetch step would pass whether or not this wiring exists.

Criterion 6, the subject of this gap-closure run, is now genuinely met: the ceremony has run and passed twice against a real TLS-terminating Phoenix with server-side route evidence, and the required-test gate is independently proven fail-closed. The one flagged residual risk there (the live-server layer's aggregate CI gate cannot currently go green because of the pre-existing, unrelated `SaveEndToEndTests` failure) is correctly filed as a deferred item, not a gap of this phase — but it is worth the next operator's attention, since it means hosted CI will not show a green live-server layer until that separate bug is fixed, even though the pairing ceremony itself is sound.

The hosted runner's own TLS provisioning path (`start_native_services`/`cleanup_native_services` in `run-mac-verification.sh`) has still not been exercised by an actual hosted CI run — only contract/static checks and the operator's local sudo-gated run have executed the underlying `mac-ci-tls.sh` logic. This is an honest residual risk, not a fabricated pass, and should be watched on the next push.
