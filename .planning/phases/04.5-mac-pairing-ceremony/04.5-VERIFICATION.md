## Gaps Summary

Two of the six ROADMAP success criteria fail on direct inspection of the shipped code, not merely on missing test coverage:

1. **Criterion 5 (trust-on-first-use pinning) is not delivered.** `PairingCoordinator.redeem()` discards the one signal (`writeCapturedCertificate`'s return value) that would tell it pinning failed, `start()` doesn't require `https`, and the only end-to-end test in the whole phase pairs over plain `http://127.0.0.1:4010` — so nothing anywhere, human or automated, has ever observed `pinned-ca.der` actually being written by this ceremony. This is exactly the class of gap the code review (CR-02) already surfaced; verification independently confirms it by reading the same three files.

2. **Criterion 2 (ceremony correctness as an extracted, testable type) is not fully delivered.** The extraction itself is real and correctly shaped, but `cancel()` is only cooperative (CR-01): a user closing the pairing sheet mid-redeem can still end up with a silently-written Keychain credential and a resurrected `.paired` state after the UI has already reported cancellation. `PairingCoordinatorTests.testCancellingStopsThePollLoop` does not cover this window, so it is untested as well as unfixed.

Criterion 6 (live-server proof) is tracked honestly by the executor and REQUIREMENTS.md as not yet executed — filed here as `deferred`, not a fresh gap, since it is already the acknowledged next step and re-flagging it would double-count the same fact. However, it is worth noting for whoever closes the two gaps above: fixing CR-01/CR-02 should happen *before* that live-server run is finally executed, because the current `PairingCeremonyTests` (a) cannot prove criterion 5 even if run, since it uses `http`, and (b) would not exercise the cancellation race in CR-01 at all, since it never cancels mid-ceremony. Closing gaps 1 and 2 first, and adding coverage for both to the live-server test, avoids spending the one "real Phoenix" run on a test that still can't prove the two things most in question.

Criteria 3 and 4 are solidly verified by direct source reading and matching unit/reachability tests.
