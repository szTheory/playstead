<objective>
Close VERIFICATION gap 2 (ROADMAP criterion 2): make the extracted ceremony correct under cancellation, not merely extracted.

Purpose: `cancel()` today only sets Swift's cooperative cancellation flag. Neither `pollLoop()` nor `redeem()` re-checks anything after its network `await` resumes, so a user dismissing the pairing sheet mid-redeem can still have a credential silently written to the Keychain and `.paired` flipped back on after `cancel()` already set `.idle`. `testCancellingStopsThePollLoop` only cancels while `.pending`, so the window is untested.

Output: a monotonic generation token checked after every `await` before any commit, and three tests that cancel with a real request genuinely in flight.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User intent (sheet dismissal) → ceremony commit points | The user's cancellation must be authoritative over an in-flight network call. |
| Pairing ceremony → login Keychain | A durable secret written after the user withdrew consent is the defect this plan closes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.5-05 | Elevation of Privilege | `PairingCoordinator.redeem()` post-await commit | high | mitigate | Task 1's generation guard precedes `storeCredential`, so a cancelled ceremony cannot durably grant this Mac a scoped credential the user declined. |
| T-04.5-06 | Tampering | `PairingCoordinator.start()` post-await state assignment | medium | mitigate | Task 1's guard prevents a cancelled ceremony from resurrecting `.awaitingApproval` and starting an orphaned poll loop against a request nothing will redeem. |
| T-04.5-07 | Repudiation | UI reports `.idle` while a credential exists | high | mitigate | The guard makes displayed state and Keychain contents agree; task 2's tests assert both together, never state alone. |
| T-04.5-08 | Denial of Service | server-side pairing request left un-redeemed after cancel | low | accept | The server already expires stale requests (`ExpireStaleRequestsWorker`); no client change is warranted. |
| T-04.5-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — this plan installs no packages and adds no dependency to any manifest. |
