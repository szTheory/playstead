<objective>
Make the criterion-6 proof permanent and fail-closed in CI, then — and only
then — flip PROT-01.

Purpose: 04.5-04 makes the ceremony test able to pass and records one genuine
pass. Without this plan that pass rots: the hosted runner still serves plaintext,
and `PairingCeremonyTests` still sits outside the live-server layer's
`--required-test` allowlist, so a red or never-run ceremony test would not fail
the gate. This project has four recorded fail-open CI modes from Phase 03.5; the
promotion is only real if a red ceremony test is *demonstrated* to fail the job.

Output: TLS provisioning, trust, and teardown wired into the hosted runner; the
ceremony test promoted to `--required-test` and anchored against future removal;
a self-test that proves the gate fails closed; PROT-01 completed with cited
evidence.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI harness → macOS System keychain | The hosted runner installs and must remove a trust root; anything left behind widens machine trust for later jobs on that runner image. |
| xcresult JSON → gate decision | The layer verifier turns untrusted test-result data into a pass/fail verdict for the whole job. |
| Published evidence → downstream verification | `verify-hosted-evidence.yml` consumes the manifest this runner writes; a manifest that omits the ceremony test would let an unproven criterion look proven. |
