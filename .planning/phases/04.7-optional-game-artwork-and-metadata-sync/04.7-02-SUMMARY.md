# Phase 04.7 Plan 02: Isolated Image Decode and Private Media Custody Summary

Playstead now decodes uploaded PNG/JPEG in a pinned Linux sidecar and stores private source media only after validation, with the exact original bytes and safe derivative tracked separately.

## Accomplishments

- Added a Linux libvips service using a private Unix socket. The decoder has no network, credentials, canonical storage mount, Docker socket, or app API access. The app fails closed if its required production socket is absent.
- Pinned the Debian Trixie base image by digest `sha256:a29215f6a35e51e22adffa17f89e9d2ef06214e64a2bad10d765c46aea49f11f` and libvips packages at `8.16.1-1+deb13u2`. The official libvips source license is LGPL-2.1-or-later; no third-party decoder container image was adopted.
- Enforced a 20 MiB input bound, PNG/JPEG-only full decode, one frame, 8192-pixel axis and 40 MP bounds, metadata removal, and a 1600-pixel derivative bound. Two active decodes are admitted by the shared sidecar semaphore.
- Set the sidecar to non-root UID 11001, network mode `none`, read-only root, all capabilities dropped, `no-new-privileges`, pinned seccomp, 32 PIDs, one CPU, 512 MiB memory plus swap, and 64 MiB scratch tmpfs. The decoder process group is killed at its 10-second child deadline.
- Added owner-scoped `metadata_media` records, a ten-item/game quota, exact original SHA-256/size/MIME and provenance, and separate derivative references. The migration cascades media records with owner/game deletion; blobs remain in the existing CAS and are discoverable through the normal blob table and backup/export path.
- Added authenticated upload and original/derivative reads. Uploads require declared length, SHA-256 `Repr-Digest`, and an idempotency key. The bounded controller consumes the request before replay handling; image decode and validation happen before either CAS write.
- Added owner-scoped idempotent derivative detachment. The item no longer exposes a removed derivative while its exact original stays readable; the CAS object remains stored because its content hash may be shared.
- Plain UTF-8 text is capped at 64 KiB. Invalid images, oversize inputs, missing decoder isolation, cross-owner reads, digest mismatch, and item-limit overflow fail without changing ROM or save identities.

## Decisions Made

- The single shared Compose sidecar is the global admission point for all app replicas; no second app-node-local decode pool was added.
- A dedicated `metadata_media` table is required because a game can own up to ten independent media records even when no description is selected. It keeps ownership, immutable original CAS identity, and derivative identity explicit without changing ROM or save identity.
- The upload body uses the existing digest and idempotency contract. Body consumption precedes replay handling to avoid leaving raw media bytes unread on a keep-alive connection.
