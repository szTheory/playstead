## Top 3 Priority Fixes

1. **Show source/device on conflict alternatives** — conflict resolution works, but the player cannot compare the provenance required by the design contract — render each alternative's recorded source and device beside its value.
2. **Match the consent, candidate, and empty-description copy contract** — users see different confirmation language from the reviewed disclosure — use the specified consent/action labels and the exact empty description remedy consistently.
3. **Replace raw `6`/`4` point gaps with spacing tokens** — the new metadata surfaces drift from the shared rhythm — map those gaps to the nearest declared `DesignTokens.Spacing` values.

## Detailed Findings

### Pillar 1: Copywriting (2/4)

- **WARNING — contract copy drift.** `MetadataSettingsView.swift:112-120` labels consent actions “Enable for this game” / “Revoke provider access” and search results use “Select this title” at `:339`; the contract calls for “Enable IGDB lookup”, explicit “Turn Off” confirmation, and “Use this match”. These labels obscure the exact operation and rights review the contract promises.
- **WARNING — empty descriptions are underspecified.** `GameDetailView.swift:82-85` says “No description yet.” while the contract requires “No description available.” The latter describes the field state without implying a future load is underway.
- Other copy is generally contextual: candidate results disclose system/confidence (`MetadataSettingsView.swift:333-340`), conflict controls explain both alternatives (`MetadataCorrectionView.swift:105-117`), and artwork labels clearly distinguish a “Game screenshot” (`GameDetailView.swift:164-190`).

### Pillar 2: Visuals (3/4)

- **WARNING — metadata pane density.** `MetadataSettingsView.swift:70-300` stacks provider disclosure, per-game preparation toggles, cache accounting, and private upload controls in one long content column. `LibraryShellView.swift:558-583` makes it scrollable, so this is not a clipping defect, but it weakens the requested “avoid a settings wall” progressive disclosure. Grouping advanced preparation/cache actions behind concise expandable sections would preserve the simple lookup path.
- The core visual composition is contract-aligned: detail places cover/title and direct readiness-aware action before description and screenshot (`GameDetailView.swift:35-105`); the card slot keeps a 44×44 image/monogram (`ArtworkIdentityView.swift:93-130`); the detail/gallery use bounded frames and scrolling (`ArtworkIdentityView.swift:96-97`, `ArtworkGalleryView.swift:33-75`).
- The inspected synthetic bitmaps include long disclosure, long description, conflict, cache, settings-navigation, and overflow states. Their black/transparent unused regions are a limitation of isolated mounted controls, not evidence about the full app window. No desktop composition screenshot was available to assess the final 60/30/10 surface hierarchy or card-grid art in context.

### Pillar 3: Color (3/4)

- **WARNING — distribution not fully observable.** The implementation uses semantic background/surface/text/separator colors and system accent (`DesignTokens.swift:48-58`); links are native `Link` controls (`MetadataSettingsView.swift:96`, `:338`), and accent-colored selection remains limited to existing library focus/favorite states (`GameRowView.swift:190`, `:281`, `:649`). The only fixed hex in the audited design tokens is the declared destructive red `#EF4444` (`DesignTokens.swift:50`). The synthetic control crops cannot verify the contract's 60% background / 30% surface / ≤10% accent balance at window scale. Capture a full native settings/detail composition before making a stronger color-distribution claim.

### Pillar 4: Typography (4/4)

- Semantic SF styles are consistently used across the audited surfaces: `.psBody`, `.psLabel`, `.psLabelEmphasized`, `.psHeading`, and `.psDisplay` (`DesignTokens.swift:61-69`; usages in `GameDetailView.swift:48-54`, `ArtworkGalleryView.swift:20-22`, and `MetadataSettingsView.swift:82-98`). The emphasized style is semibold; the rest inherit regular system styles, matching the contract's two-weight hierarchy.
- Long descriptions wrap in the detail view (`GameDetailView.swift:75-80`) and long correction descriptions use a multiline field (`MetadataCorrectionView.swift:41-45`). The inspected long-text bitmap remains readable. No font-size or weight deviation was found in these files.

### Pillar 5: Spacing (2/4)

- **WARNING — arbitrary spacing values.** The contract requires existing spacing tokens only. `MetadataSettingsView.swift:89` uses `spacing: 6`; `:137`, `:184`, `:265`, and `:341` use `.padding(.vertical, 4)`. `MetadataCorrectionView.swift:104` also uses `spacing: 4`. Convert these to the closest declared `xs`/`sm` token and retain the existing 8/16/24/32-point token rhythm elsewhere.
- Card/detail/artwork geometry matches declared sizes (`ArtworkIdentityView.swift:93-97`, `GameRowView.swift:182-183`) and no other arbitrary point spacing was found in the audited component layout.

### Pillar 6: Experience Design (3/4)

- **WARNING — conflict provenance is incomplete.** `MetadataCorrectionView.swift:105-110` displays the two values as “Your edit” and “Current server value”, but does not show the source/device for either alternative. The values can still be explicitly resolved, and production journey evidence passes; this is a remaining UI contract gap rather than a broken conflict-resolution flow. Add each alternative's recorded source and device beside its value.
- **Resolved since the original audit — expiry enforcement.** `MetadataArtworkReference` now resolves the earliest linked selection/source/provider-evidence expiry and marks missing or malformed provider policy invalid while allowing private user media without expiry (`ArtworkIdentityView.swift:21-74`). The mounted thumbnail refuses invalid/expired selections, passes expiry to the cache, clears loaded art at deadline, and ignores late canceled-task failures (`:204-285`). The cache checks deadlines before cache/network use and constrains stored expiry (`MetadataMediaClient.swift:18-57`; `MetadataMediaCache.swift:52-100`, `:162-177`). Evidence `04.7-09-ARTWORK-EXPIRY-EVIDENCE.json` records exact 1/1/0-fail/0-skip unit and rendering runs, including red-thumbnail before/after-deadline and late-error replacement proofs. This closes the previously reported expiry gap; it does not claim external-provider or hardware qualification.
- The phase evidence remains strong for core task completion: the 53-state fixture/action receipt reports 45 settings and 8 correction states passed (no skips); rendering evidence reports all 53 mounted fixtures passed; the live production-composition journey passed 1/1 with no skips and exercised three media exports, offline field corrections, conflict resolution, reset, loaded artwork, and stable IDs. These are automated native proofs, not human UAT or physical controller/Apple HID qualification.
- Empty, loading, cancellation, retry, and error affordances exist across settings and artwork (`MetadataSettingsView.swift:133-135`, `:223-233`; `ArtworkIdentityView.swift:119-146`). Gallery has keyboard movement/exit and controller-B close handling (`ArtworkGalleryView.swift:76-86`); gallery-open dismissal restores focus to the invoking button (`GameDetailView.swift:109-110`).
