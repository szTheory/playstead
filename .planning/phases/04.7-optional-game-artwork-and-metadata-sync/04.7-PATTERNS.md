## Pattern Assignments

### Server provider evidence and context

**Analogs:** `playstead-server/lib/playstead/recognition/provider.ex` and `playstead-server/lib/playstead/catalogue.ex` (both tracked).

`recognition/provider.ex` is a small provider boundary: stable provider name/version and an evidence result (lines 15-40):

```elixir
@type confidence :: :exact | :header | :filename | :user
@callback name() :: String.t()
@callback version() :: String.t()
@callback recognize(facts :: map(), format_evidence :: {atom(), atom(), map()} | nil) :: result()
```

Use the seam and persisted provenance concept, but define separate metadata match evidence/confidence and never pass ROM hashes or filenames unless the user separately opted into that field. Recognition confidence certifies a different claim and must not be reused. For ownership/scoping, copy the context pattern in `catalogue.ex` lines 211-248: accept `%Scope{user: user}`, constrain every query by `user.id`, and use an owned lookup that returns `nil` for another user's row. Controllers should pass the authenticated scope/device into the context, not accept `user_id` from request parameters.

### Authenticated API, idempotent mutation and streamed original upload

**Analogs:** `playstead-server/lib/playstead_web/controllers/api/v1/saves_controller.ex` and `playstead-server/lib/playstead_web/plugs/idempotency.ex` (tracked).

`SavesController` lines 30-55 reads the authenticated device, validates the command ID, obtains the declared size/digest assigned by the request plugs, checks a hard size limit, and streams through `Blobs.put_stream/3`; lines 67-77 records the uploaded digest against the authenticated owner. Its separate metadata commit is the closest existing analogue for “bytes first, selection/manifest commit second.” Reuse the request pipeline style in `router.ex` (the mutating routes at lines 295-307 use `[:api, :device_auth, :idempotency]`; streamed routes are separate because the body cannot be fingerprinted) and `Idempotency.execute/4` for metadata mutation receipts. Ensure final manifest/reference commit is owner-scoped and idempotent; an upload alone must not publish a selected artwork asset.

Private originals must use the existing `Playstead.Blobs.Store` contract. Its lines 8-12 explicitly reserve deletion for temporary objects; lines 40-54 stream chunks and abort uncommitted writes; lines 43-51 require fsync, re-hash and atomic content-addressed commit. Never put private originals into the provider cache or transform them in place. Extend export layout/sidecar/verifier and the canonical blob inventory so private originals are included with exact SHA-256/size and provenance; provider cache bytes remain derived and excluded. Removal of a private original must be an explicit canonical asset operation, not cache reclaim.

### Durable bounded work and image processing boundary

**Analog:** `playstead-server/lib/playstead/import/session_worker.ex` (tracked), plus `config/config.exs` lines 38-53.

`SessionWorker` lines 33-36 uses an Oban queue, attempt limit, and job uniqueness. Lines 48-49 fixes the stream chunk size; its batch loop (lines 99-100 onward) processes one bounded batch, checks persisted control between batches, and self-chains durable work. Follow this lifecycle, persistent state, cancellation, idempotency, and retry conventions. Do not create one unbounded task per image or run decoding in LiveView/request processes.

The current Oban queues are `default: 10, import: 1, recovery: 1` (`config/config.exs:38-47`). Route all user-upload and provider-image decode/derivative work through one dedicated shared decoder queue capped at **two** workers for the single-server deployment. Do not split into independent “provider decoder” and “upload decoder” queues: that would permit four decoders. The cap must be enforced by the queue used in production composition, not merely a constant in a helper. If a deployment runs multiple worker nodes, explicitly enforce or document a deployment-wide bound; per-node Oban concurrency alone multiplies across nodes.

**No image decoder analog exists in the tracked server source.** `rg` found no ImageIO, libvips/Vix/ImageMagick dependency, `System.cmd` image pipeline, or bounded subprocess helper. The tracked `System.cmd` uses (`recovery/compose_runner.ex`, `readiness.ex`, blob disk checks) are fixed administrative commands, not a safe untrusted-image processing boundary. Apple ImageIO/CoreGraphics is Mac-only and cannot validate server uploads in the Linux release.

Recommended candidate: a single Linux `libvips` helper (`vipsthumbnail`/libvips thumbnail API) inside a no-network, resource-limited helper container called only by the shared two-worker queue. The official [libvips thumbnail documentation](https://www.libvips.org/API/8.17/using-vipsthumbnail.html) establishes that it reads source images and writes bounded-size PNG/JPEG thumbnails; its [developer checklist](https://www.libvips.org/API/8.17/developer-checklist.html) also documents a pathological progressive JPEG using 4 GiB, so pixel caps alone do not replace an OS-enforced memory/time limit. Pass only a staged file and fixed operation, enforce wall-clock, memory, dimensions/pixel and single-frame limits externally, allow PNG/JPEG only, and re-encode display derivatives. Do not shell-interpolate user data or provider URLs. Qualify helper inputs/outputs, reject unsupported/animated formats, and pin the actual helper image digest/version only after verifying the selected build and release packaging. This is a recommendation, not a dependency currently present in the repository; no unverified package version is supplied here.

Provider enrichment should remain a separate behavior/Req adapter from recognition, with provider/version and consent revisions persisted in evidence. Req is already the project-preferred client (`playstead-server/AGENTS.md`); don't add an SDK/client dependency. Before provider image retrieval is enabled, satisfy the research's exact IGDB private-serving rights checkpoint; API cache permission is not a verified artwork sublicense. Keep metadata lookup and private upload functional while image retrieval remains fail-closed.

### Protocol journal, snapshot and compatibility

**Analogs:** `playstead-server/lib/playstead/sync/snapshot.ex`, `sync/entity_kind.ex`, `sync/curation_payload.ex`, and `protocol/capabilities.ex` (tracked).

`Snapshot.read/2` lines 96-125 reads page state and cursor in one transaction, pins the as-of position, then emits each registered branch from that transaction. Add metadata selection to that same consistent snapshot/reset model. `EntityKind` lines 25-37 rejects unregistered kinds; `Capabilities` lines 43-59 keeps the public envelope fixed and versions optional feature support inside the existing namespace ranges. Do not silently extend the frozen `catalogue/payload.ex`; the current entity kinds are `device pairing catalogue job transfer save curation`, so `metadata` needs an additive protocol/capability decision and compatible payload/schema/examples before a native client consumes it.

`CurationPayload.build/1` is the better inner-shape example (one journal kind with typed payload variants) than changing the catalogue representation. Preserve each provider evidence row separately from selected/corrected fields; correction updates and resolution must be idempotent user mutations. Conflicting user values must preserve both alternatives and require explicit resolution. Snapshot/reset must include selected metadata at the same cursor, while media availability and device cache rows remain local.

### Mac transactional mirror, outbox, cache and UI

**Analogs:** `playstead-mac/Playstead/Persistence/CatalogueStore.swift`, `Sync/JournalApplier.swift`, `Sync/Outbox.swift`, `Persistence/Migrations.swift`, `Cache/CacheObjectStore.swift` and `Library/GameRowView.swift` (all tracked).

`CatalogueStore.swift` lines 3-14 documents the key invariant: page writes are caller-wrapped in one `LocalStore.transaction`; lines 22-32 validate at the single write chokepoint; lines 89-108 implement snapshot replace/reset. A new metadata selection store should be coordinated by `SyncEngine` so journal page plus cursor commit atomically, and full cursor reset replaces synced selections without clearing unrelated canonical private files. `JournalApplier.swift` lines 141-195 shows kind dispatch and skip/count behavior for unknown additive data; add a metadata branch with a typed decoder and deterministic outcome. `Migrations.swift` lines 3-11 and 52-60 shows additive SQLite schema setup and opaque cursor persistence; use new tables/columns with foreign keys, explicit source/evidence/selection revision and local-only cache state separated.

`Outbox.swift` lines 54-61 and 96-103 show optimistic local write plus durable outbox entry in one transaction and stable idempotency key across retries. Reuse `CurationIntent`/`OutboxWorker` composition for offline correction/selection edits; include base revision so server conflicts can retain both alternatives. Do not build a second metadata sync loop.

`CacheObjectStore.swift` lines 4-22 explains why a central object ledger owns physical object accounting; `QuotaManager.swift` measures used bytes against quota/floor, while `EvictionPlanner` owns eligibility/removal. Add a distinct media class/ledger and reclaim predicate; never reuse the ROM eviction set for private originals, saves or provider objects whose terms prohibit refetch/use. Keep server's provider cache and Mac's local offline cache distinct from immutable private originals.

Extend `GameRowView` and `LibraryShellView`; the row already owns readiness and direct action controls (`GameRowView.swift:69-84, 779-784`) and the shell owns selected-game/controller focus and bounded destination routing (`LibraryShellView.swift:271-303, 362-372`). Artwork is content inside the existing identity slot, not a new readiness condition. Follow `SystemMonogramView` for honest missing media, `DesignTokens`, `AccessibilityIdentifiers`, and the existing controller navigation dispatcher. The detail/gallery should be a focused destination with keyboard Escape/B close, image traversal, accessible labels/actions, and selection/focus restoration; no new sidebar category or network work on the launch path.

## Shared Patterns

### Ownership and authorization

Use current authenticated device/scope to derive owner identity; every metadata, candidate, manifest and media-byte read/write is owner-scoped. Opaque IDs are not authorization. Stream private original bytes only through authorized routes; provider credential and local path never leave server/client boundary.

### Stable original bytes versus derived media

Private originals: stream with declared size/digest checks into `Playstead.Blobs`, hash exact bytes, immutable CAS commit, manifest/provenance, export and canonical backup inventory. Provider images: separate policy-bearing, reclaimable cache objects, constructed URLs from validated provider ID and fixed host/size allowlist; not canonical blob custody. Client display thumbnails/cache are also derived and device-local.

### Boundedness

Enforce compressed input bytes while streaming, fixed MIME allowlist by content sniff plus successful full decode, dimension/pixel/frame/time/memory caps, per-user and instance request/cache limits, retry ceiling/backoff, cancellation, and shared decoder queue concurrency 2. Do not count DB queue concurrency as subprocess memory isolation; the Linux decoder needs an independently enforced resource boundary.
