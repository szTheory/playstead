## Accomplishments

- Extended the metadata mirror to retain typed selections, per-field revisions and sources, deleted fields, evidence, conflicts, and tombstones. Journal page/reset and cursor writes remain transactional, and rollback tests confirm local game-cache data is preserved.
- Added an optimistic metadata correction intent to the existing outbox. The durable envelope retains the base field revision; retries use the same stored idempotency key and reconnect drains through `APIClient` and `OutboxWorker`.
- Decoded the server's structured metadata-conflict response, persisted current and incoming alternatives, and held the row in an explicit conflicted state. A later owner edit resolves the conflict against the current field revision; unrelated curation can still drain.
- Persisted the artwork cache index, pin and expiry fields in SQLite while keeping verified bytes in the profile-local cache directory. Restart recovery validates the digest and size; expired or stale identities are removed. Unpinned refetchable entries are the only eviction candidates, and pinned-capacity refusal is structured.
- Added an authenticated client for the server's owner-scoped derived-media endpoint. It checks response type, exact size and SHA-256, coalesces concurrent requests, and accepts no provider URL or token input.
- Composed metadata edits and media retrieval in `AppEnvironment`, exposed the coordinator-facing edit/fetch/pin seams, and wired cache usage into the separate Storage settings artwork budget.
- Added an expected-digest cache-hit check so a stable media ID cannot return bytes that no longer match current server metadata.
