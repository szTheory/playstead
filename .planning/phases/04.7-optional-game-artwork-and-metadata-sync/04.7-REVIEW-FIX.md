## Remaining Safety Gap

`Playstead.Blobs.Store` only exposes deletion for uncommitted temporary files. It intentionally has no operation for deleting committed content-addressed originals, since those bytes may be shared or canonical. Capacity rejection occurs before writes, changeset validation occurs before publication, and a rejected manifest SQL insert now occurs before publication. The remaining failure window is the shared CAS/transaction boundary: `LocalDisk.commit/2` renames a temp file into canonical storage before inserting the blob row, and `metadata_media` is committed in an enclosing transaction. A storage failure after the first object, an outer transaction commit failure after publication, or a process crash in that interval can still leave unreferenced bytes. The importer also adopts temp files into CAS through this same publication path. No supported adapter operation can safely remove those canonical bytes without proving cross-domain references and serializing concurrent writers, so this fix preserves them. A durable staged publication/recovery protocol or reference-aware collector remains future work outside this phase's authorized scope.

The exact test manifest already had concurrent edits from the root phase executor. I added rows for the two new exact test identities to the shared manifest for these runs, but left the manifest uncommitted so the root can preserve and commit its existing changes together. Source and test fixes are committed independently per finding.
