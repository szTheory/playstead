# Phase 4.7 metadata wire decision

The first durable presentation field uses an additive metadata entity kind. It is keyed by the existing `asset_set_id`; it does not replace or mutate the frozen catalogue representation, imported bytes, save-line identity or save revisions. This implements the preauthorized `metadata-kind` recommendation under D-14 and D-15.

```protocol-decision
{
  "choice": "metadata-kind",
  "entity_kind": "metadata",
  "payload_version": 1,
  "identity_key": "asset_set_id",
  "revision": "owner_monotonic_revision",
  "tombstone": "deleted_at",
  "selection_resource": {
    "method": "POST",
    "path": "/api/v1/metadata/:asset_set_id"
  },
  "media_resource": {
    "method": "GET",
    "path": "/api/v1/metadata/:asset_set_id/media/:media_id",
    "status": "reserved_until_media_plan"
  },
  "capability": {
    "namespace": "app",
    "feature": "metadata_selection",
    "version": "1.1.0",
    "required": false
  },
  "snapshot_branch": "metadata",
  "reset_behavior": "reconstruct_at_snapshot_cursor",
  "old_client_behavior": "ignore_optional_kind",
  "migration_policy": "additive_optional_kind_and_snapshot_branch"
}
```

## Compatibility and migration

- Mutations require an authenticated paired device, an `Idempotency-Key`, and an existing asset set owned by the authenticated user. The server derives owner identity from the device scope.
- `POST /api/v1/metadata/:asset_set_id` selects private text metadata. `GET /api/v1/metadata/:asset_set_id` reads the caller's current selection. Media bytes remain unimplemented in this plan; the typed media resource is reserved for a later plan and must have its own custody and rights gates.
- Version 1 has one optional `metadata` change kind and one `metadata` snapshot branch. Every page in a reset uses the existing snapshot cursor; the materialized branch is read at that same as-of boundary.
- The server may add this optional kind and branch without changing the frozen catalogue payload or requiring an old client to understand presentation metadata. Old clients ignore the unknown optional kind; new clients rebuild the branch from a full snapshot after reset.
- Storage adds an owner-scoped selected-description row and a migration. It does not update asset-set, game-byte, manifest, save-line or save-revision identity. A later payload revision or incompatible identity change requires a new versioned contract and migration path; this v1 representation is retained.
- Metadata selection is an optional `app` 1.1.0 capability. This reuses an existing range without adding a namespace or changing the frozen capabilities envelope. Clients that declare app 1.0.0 keep existing behavior and ignore the optional metadata kind; updated clients can declare app 1.1.0. The fixed public capabilities envelope remains unchanged.
