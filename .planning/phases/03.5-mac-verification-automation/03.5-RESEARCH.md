### CI Test Topology

- **D-01:** Add one unfiltered, required GitHub Actions macOS job on every push and pull request. Pin a numbered `macos-*` image and an explicit installed Xcode version; assert `sw_vers`, runner architecture, and `xcodebuild -version` before testing. Missing/drifted toolchains fail loudly rather than silently selecting a new environment.
- **D-02:** Build the Mac app once with `build-for-testing`, then run independent `test-without-building` layers for: (1) all existing `PlaysteadTests`, (2) deterministic render/snapshot tests, (3) fixture-driven XCUITest interaction plus live accessibility, and (4) one focused real-server pairing/snapshot spine. Rendering and UI layers run serially. Aggregate exit codes so later evidence still runs after an earlier layer fails; do not add automatic retries.
- **D-03:** Every UAT-mapped test must be named explicitly and proven discovered, executed, non-skipped, and passed. Use expectation-based waits, exact identifiers and postconditions, and nonempty state guards; fixed sleeps, percentage-only screenshot checks, and "test target exited zero" without test-discovery proof are prohibited.
- **D-04:** Standard GitHub-hosted macOS runners cannot run the existing Docker Compose stack. Preserve the existing Linux `compose-smoke` job as the deployment-topology proof, and start PostgreSQL plus the real Phoenix application natively beside XCUITest in the macOS job for the client/server behavior proof. Clarify Phase 3.5 success criterion 4 to state this split explicitly. Do not require a paid Intel larger runner, secret-dependent cross-job tunnel, or externally exposed transient service. — **Reversibility:** costly — switching to paid/self-hosted Compose-capable Mac infrastructure changes the public CI administration, trust, cost, and maintenance model.
- **D-05:** Upload failure-only `.xcresult` bundles, screenshots, snapshot reference/actual/diff images, environment fingerprints, redacted accessibility-tree dumps, focus traces, and sanitized app/server logs with short retention. Do not cache DerivedData across runs; a fresh VM builds once. Only lockfile-backed dependency downloads may be cached later.

### Pairing and Deterministic Test State

- **D-06:** The focused live proof uses production setup/import/pairing domain functions and real HTTP endpoints. Create the owner through the real setup context, seed one deterministic synthetic non-ROM catalogue sentinel through custody/import contexts rather than raw SQL, create and redeem the pairing request through the public API, and automate trusted-owner approval through the production pairing context. Approval must assert the exact request ID, returned display code, unique claimed device label, and the sole expected pending request. Existing browser tests remain the proof of the human Devices approval UI.
- **D-07:** Give every test a unique application-support root and disposable Keychain. A compile-gated UI-test bootstrap reads a redeemed credential from a mode-`0600` temporary file, deletes the file, stores the credential through the real `KeychainStore`, and then requires the app to authenticate through the normal `KeychainStore.loadCredential` path. Credential overrides, launch-argument secrets, shared login-Keychain mutation, `security -A`, and silent fallback after Keychain failure are prohibited.
- **D-08:** Add a release guard proving the credential bootstrap, deterministic profile loader, their environment keys, and their symbols are absent when the UI-testing compilation condition is disabled. Test-only behavior must fail closed and must not create a production pairing bypass. — **Reversibility:** costly — a leaked test hook would be a release-security defect and require removing every call site plus auditing shipped binaries.
- **D-09:** Deterministic profiles are a finite compile-gated enum covering only the required states: empty library, populated library/curation/reorder, paused/active download queue, quota block/reclaim, and storage. Profiles seed via `LocalStore`, curation, queue, pin, quota, and CAS APIs with fixed synthetic IDs, bytes, digests, positions, and timestamps. Arbitrary JSON execution, arbitrary SQL, copied production databases, copyrighted ROMs, and proprietary BIOS data are prohibited.
- **D-10:** The live snapshot proof is non-vacuous only when it asserts the sentinel's exact title and asset-set ID in the real app, at least one rendered library row, a nonempty stored cursor, sanitized server evidence of a successful `/api/v1/snapshot`, zero `/api/v1/blobs/` requests, and empty `objects/` and `partials/` directories. Clear the local mirror and relaunch without the handoff file after adding a second server sentinel; the second sentinel must appear, proving the credential survived in Keychain and the first SQLite mirror did not fake success.
- **D-11:** Serialize the live Keychain/server spine and clean up through a fail-safe trap. Never attach credentials, Keychain dumps, mode-`0600` handoff files, `.env`, databases, raw pairing responses, ROM filenames/hashes, or unredacted logs to CI evidence.

### Rendering and Snapshot Contract

- **D-12:** Use an exactly pinned, test-target-only Point-Free `SnapshotTesting` dependency behind one project-owned `PlaysteadSnapshot` wrapper. Validate the selected version on the pinned runner, including an intentional mismatch that must produce an ordinary failed assertion plus reviewable artifacts. Do not make `ViewInspector` the primary harness and do not build a project-owned PNG decoder/comparator unless the chosen dependency fails the validation spike.
- **D-13:** Pixel snapshots prove only genuinely visual claims: the rendered 280×158 card, two-line title behavior, three-zone anatomy, all seven status glyph/shape/color treatments, absence of a cover-art surface, representative populated and empty library/curation states, and Downloads/Quota/Reclaim/Storage presentation. Prefer focused components/contact sheets plus a small number of representative shells over giant whole-window snapshots.
- **D-14:** Exact semantic XCTest assertions prove the complete sidebar order, registry-ordered nonempty systems and conditional Unidentified-last rule, equality with the complete seven-status set, every priority combination, exactly one selected status slot, locked labels/copy, empty-shelf hide/show behavior, 280×158 point constants, disjoint system/status token vocabularies, and a title-independent presentation seam. Pixel similarity never substitutes for these domain assertions.
- **D-15:** Every fixture asserts its exact nonzero item count and expected state set. Every render asserts exact pixel dimensions plus a nonempty/nonuniform content bounding box. Comparator self-tests must prove a meaningful visual mutation fails and calibrated antialiasing noise passes. Tolerances may not be loosened merely to make CI green.
- **D-16:** Render with fixed synthetic data, clock, UTC, `en_US_POSIX`, active state, animations disabled, standard Dynamic Type, explicit light/dark appearance, 2× scale, and SDR 8-bit sRGB on the asserted runner/Xcode/architecture fingerprint. Add targeted Large-text and long-Unicode/title cases. Do not baseline ambient system appearance, every locale, or every scale before those become supported contracts.
- **D-17:** CI always runs with snapshot recording disabled and fails on missing references. Baseline refresh is a manual workflow on the same pinned environment that emits candidate artifacts only. A maintainer reviews named side-by-side diffs and commits intentional baselines with the corresponding source/test change; the workflow never commits, auto-accepts, or mass-records snapshots.

### Pattern 1: One Build, Explicit Independent Test Layers

Use one fresh DerivedData directory and `build-for-testing`, then serial `test-without-building` invocations selected by shared test plan. Capture each exit status without short-circuiting and run the result verifier after every invocation. `xcodebuild` 26.6 exposes `-resultBundlePath`, `-derivedDataPath`, `-testProductsPath`, `-testPlan`, `-only-testing`, `build-for-testing`, and `test-without-building`. [VERIFIED: local `xcodebuild -help`, 2026-08-31]

```bash
# Pattern only; the planner selects the script and test-plan path names. [ASSUMED]
xcodebuild build-for-testing -project Playstead.xcodeproj -scheme Playstead \
  -derivedDataPath "$RUN_DERIVED_DATA"
xcodebuild test-without-building -project Playstead.xcodeproj -scheme Playstead \
  -testPlan "$LAYER_PLAN" -derivedDataPath "$RUN_DERIVED_DATA" \
  -resultBundlePath "$LAYER_RESULT"
```

Do not use shell `set -e` across layers. Store statuses in a small fixed array, always sanitize/export evidence, then return nonzero if any layer or discovery assertion failed. [ASSUMED]

### Pattern 2: Compile-Gated, Fail-Closed UI Test Composition

At compile time, the app target gains a UI-testing compilation condition only in a dedicated testing configuration. At runtime, the bootstrap accepts only a finite profile identifier and/or a path to a mode-`0600` credential handoff. It validates ownership/mode, decodes a fixed schema, deletes the handoff before storing, writes through real `KeychainStore`, and aborts the test launch on any failure. [ASSUMED; locked behavior from D-07–D-09]

The release guard must perform both checks:

1. Build/archive without the UI-testing compilation condition and inspect the binary/string/symbol tables for every chosen hook and environment-key name. [ASSUMED]
2. Compile a test proving the production composition root cannot reference the test-only types when the flag is absent. [ASSUMED]

The existing `AppEnvironment` silently falls back from failed SQLite initialization to `LocalStore.inMemoryFallback()`—quoted verbatim: `let store = (try? LocalStore(paths: paths)) ?? LocalStore.inMemoryFallback()`. [VERIFIED: `playstead-mac/Playstead/App/PlaysteadApp.swift:175-188`] The UI-test path must replace that behavior with a throwing/fatal test initialization path so persistence failures cannot create a false pass, while leaving the production behavior unchanged unless separately justified. [ASSUMED]

### Pattern 3: Scoped Disposable File Keychain

Extend `KeychainStore` with an optional keychain scope. When supplied, add `kSecUseKeychain` to adds and `kSecMatchSearchList: [keychain]` to copy/update/delete queries; when absent, preserve current production dictionaries byte-for-byte in behavior. Apple’s technote states that file-based `SecItemAdd` otherwise uses the default Keychain and queries otherwise consult every Keychain in the search list. [CITED: https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains]

The CI helper should create/unlock a random temporary file Keychain, pass only its non-secret path to the compile-gated app, never add it to the user’s search list, and delete it in a trap. [ASSUMED] Do not use the data-protection Keychain for this fixture: Apple recommends it generally, but it cannot be redirected to a disposable file and requires code-signing access groups; the locked isolation requirement is the narrow reason to use the legacy file-based implementation only in UI tests. [CITED: https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains]

### Pattern 4: Finite Profiles Through Production Stores

Each profile is code, not data-driven execution. It creates one isolated root through the existing `AppPaths(root:)` entry point, whose exact directories are quoted as `“objects”`, `“partials”`, `“launch”`, `“emulators”`, `“bios”`, and `“playstead.sqlite3”`. [VERIFIED: `playstead-mac/Playstead/App/AppPaths.swift:26-47`] Seed exact known rows using production LocalStore/curation/queue/pin/quota/CAS APIs, then assert the expected nonzero counts before launching. [ASSUMED]

Keep rendering profiles and the live server profile separate. A render profile may have local synthetic catalogue rows; the live proof must begin from an empty mirror, use no profile catalogue seeding, and receive data only through the real snapshot sync. [ASSUMED; locked by D-09–D-10]

### Pattern 5: Independently Authored Accessibility Contract

Maintain a test-owned ordered inventory of stable namespaced identifiers. Query the actual XCUITest tree only after a surface-specific settled sentinel appears. Assert inventory uniqueness/nonemptiness first, then exact roles/labels/values/selected states/frames and one focused expected element after every keypress. Apple documents that Full Keyboard Access moves forward with Tab, backward with Shift-Tab, activates with Space, and moves within groups with arrow keys. [CITED: https://support.apple.com/en-gb/guide/mac-help/mchlc06d1059/mac]

Call `XCUIApplication.performAccessibilityAudit` for all supported categories after the surface settles, and filter only by exact audit type plus exact identifier and runner fingerprint. Apple explicitly recommends combining automated audits with assistive-technology testing, so a green machine audit must not be recorded as experiential VoiceOver quality. [CITED: https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app]

### Pattern 6: Production Live Fixture with a Control/Evidence File

Use one server-side Mix task [ASSUMED] as an orchestration control plane, not as a protocol bypass. It may create the setup token and call `Playstead.Setup.claim/2`, stream fixed synthetic bytes through `Playstead.Blobs.put_stream/3`, and call `Playstead.Import.import_single/4`; the source-of-truth import contract requires `original_name`, `origin`, and `size_bytes` and a `put_stream` result. [VERIFIED: `playstead-server/lib/playstead/import.ex:46-76`] Pairing request creation and redemption still go through the public endpoints quoted as `POST /api/v1/device-pairing/requests` and `POST /api/v1/device-pairing/requests/:id/redeem`; approval calls the production `Pairing.approve/2` context and explicitly forbids automatic sole-request approval. [VERIFIED: `playstead-server/lib/playstead_web/controllers/api/v1/pairing_controller.ex:16-30`, `playstead-server/lib/playstead_web/controllers/api/v1/pairing_controller.ex:51-95`, `playstead-server/lib/playstead/pairing.ex:191-228`]

Emit a minimal mode-`0600` control file for the CI parent containing only non-secret fixture IDs/state. Emit credential material only into the separate one-use handoff file, never stdout. Server request evidence should be structured counters/route names with authorization and parameters removed. [ASSUMED]

### Anti-Patterns to Avoid

- **One giant UI test:** it hides discovery/skips and makes every failure ambiguous; use named, independently invocable tests with exact postconditions. [ASSUMED]
- **Snapshotting whole windows everywhere:** it creates churn and weak diagnosis; use focused components/contact sheets plus a few representative shells, per D-13.
- **Fixed sleeps:** they are race-prone and prohibited by D-03; wait on named settled sentinels and assert the sentinel existed. [ASSUMED]
- **Reading expected focus order from the live tree or production array:** the current audit already constructs `tabOrder: elements.map(\.id)`, making equality structurally vacuous. [VERIFIED: `playstead-mac/PlaysteadTests/AccessibilityTests/AccessibilityAuditTests.swift:88-95`, `playstead-mac/PlaysteadTests/AccessibilityTests/AccessibilityAuditTests.swift:131-150`]
- **Treating `.onMove` as keyboard support:** the current production collection and queue implementations require visible keyboard-operable alternatives under D-21. [VERIFIED: code paths named by `03.5-CONTEXT.md:100-101`; locked requirement D-21]
- **Credential injection into `APIClient`:** the source has a `credentialOverride`, quoted verbatim as `private let credentialOverride: PairingCredential?`, specifically for unit stubs; live acceptance must not use it. [VERIFIED: `playstead-mac/Playstead/Net/APIClient.swift:65-99`]
- **Artifacting raw results without sanitization:** `.xcresult`, stdout and tree dumps can contain environment, paths and UI text; stage a allowlisted evidence directory and scan it before upload. [ASSUMED]
- **Changing snapshot tolerance per test:** calibration belongs in the single wrapper; an individual “make green” tolerance destroys comparability. [ASSUMED; locked D-15]

## Common Pitfalls

### Pitfall 1: Hosted Image Drift Masquerades as UI Regression
**What goes wrong:** references change because Xcode/fonts/rendering changed, not source. [ASSUMED]
**Why it happens:** GitHub updates the VM behind a numbered label and multiple Xcodes may be installed. [CITED: https://github.com/actions/runner-images/blob/main/images/macos/macos-26-Readme.md]
**How to avoid:** set `DEVELOPER_DIR` to the exact app path, assert Xcode build and ARM64, record runner image/OS/scale/colorspace, and require a reviewed environment migration for baseline churn. [ASSUMED]
**Warning signs:** broad antialias/font diffs across unrelated snapshots or changed environment fingerprint. [ASSUMED]

### Pitfall 2: Snapshot Dependency Fails While Producing Its Diff
**What goes wrong:** a mismatch crashes in diff/attachment generation rather than reporting a normal assertion. Current project issues report such failures in recent 1.19.x versions. [CITED: https://github.com/pointfreeco/swift-snapshot-testing/issues/1111]
**How to avoid:** intentional mismatch is a Wave 0 adoption gate; validate reference/actual/diff triplets before recording the suite.
**Warning signs:** test process crash, missing `.xcresult` attachment, or no actual/diff file after a known mutation.

### Pitfall 3: UI Tests Pollute or Read the Login Keychain
**What goes wrong:** the current service-only newest-wins/prune logic reads or deletes credentials outside the run. [VERIFIED: `playstead-mac/Playstead/Net/KeychainStore.swift:39-55`, `playstead-mac/Playstead/Net/KeychainStore.swift:156-227`]
**How to avoid:** explicit scoped file-Keychain query keys and a unique service namespace; never alter the host search list. [CITED: https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains]
**Warning signs:** tests pass without a handoff, multiple candidate accounts appear, system permission prompts, or the keychain file survives cleanup. [ASSUMED]

### Pitfall 4: `MIX_ENV=test` Gives a Fake Standalone Server
**What goes wrong:** HTTP work is outside the owning SQL sandbox connection, jobs are manual, or a sandbox header accidentally becomes a bypass. [VERIFIED: `playstead-server/config/test.exs:21-44`, `playstead-server/config/test.exs:107-108`]
**How to avoid:** dedicated non-sandbox `mac_ci` config with real Repo transactions and loopback endpoint. [ASSUMED]
**Warning signs:** empty snapshots despite seeded rows, sandbox ownership errors, or test-only User-Agent headers. [ASSUMED]

### Pitfall 5: Result-Bundle Success Is Mistaken for Test Coverage
**What goes wrong:** a target exits zero while a named test is undiscovered, filtered, or skipped. [ASSUMED]
**How to avoid:** allowlist every UAT test and assert discovered/executed/non-skipped/passed from machine-readable xcresult output. [VERIFIED: local `xcrun xcresulttool help`, 2026-08-31]
**Warning signs:** zero selected tests, missing test identifier, or expected fixture count never logged/asserted. [ASSUMED]

### Pitfall 6: Full Keyboard Access Is Assumed, Not Verified
**What goes wrong:** Tab behavior differs on the runner and focus tests either skip controls or never start. [ASSUMED]
**Why it happens:** Apple documents UI settings, but not a stable supported CI command-line toggle. [CITED: https://support.apple.com/en-gb/guide/mac-help/mchlc06d1059/mac]
**How to avoid:** Wave 0 may try the common `AppleKeyboardUIMode` defaults mechanism [ASSUMED], but acceptance is an in-app preflight that actually tabs through a known two-control canary and asserts focus.
**Warning signs:** no focused element after Tab or inconsistent forward/reverse canary order.

### Pitfall 7: Evidence Leaks Credentials or Content Identifiers
**What goes wrong:** raw server logs, environment, tree labels or `.xcresult` attachments reveal bearer tokens, pairing responses, paths or content metadata. [ASSUMED]
**How to avoid:** allowlist staged artifacts, structured redacted server evidence, synthetic titles only, secret-pattern scans, and failure of the upload step if sanitization fails. [ASSUMED]
**Warning signs:** `Authorization`, raw JSON redemption output, credential handoff path/content, `.env`, SQLite/Postgres files or Keychain dumps in staging. [ASSUMED]

### Pitfall 8: Roadmap Criterion 4 Is Implemented Literally Against Locked D-04
**What goes wrong:** planning attempts Docker Compose on a standard Mac runner.
**How to avoid:** explicitly update the criterion to the locked split: Linux `compose-smoke` proves deployment topology; native PostgreSQL+Phoenix on Mac proves client/server behavior. The present roadmap still says `“live server started from the existing docker-compose.yml in CI”`. [VERIFIED: `.planning/ROADMAP.md:180-195`]
**Warning signs:** Docker installation/nested-virtualization work, paid runner proposals or cross-job exposed endpoints.
