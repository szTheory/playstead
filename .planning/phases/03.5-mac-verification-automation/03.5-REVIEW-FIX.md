### WR-04: `sanitize-evidence.sh`'s log-redaction regex is a denylist that can fail open for unanchored credential shapes

**Files modified:** `playstead-mac/scripts/ci/sanitize-evidence.sh`, `playstead-mac/scripts/ci/tests/sanitizer-test.sh`
**Commit:** `db29a03`
**Applied fix:** Generalized the sensitive-key match in `sensitive_text` so
key/value pairs are caught regardless of separator (`KEY: value` as well
as the historical `KEY=value`), and added a structural pattern that
matches any `scheme://user:pass@host` connection string anywhere in a
line (not just as a standalone token), catching credentials embedded
mid-sentence in a stack trace or exception message. Added two new
negative fixtures to `sanitizer-test.sh` (`colon_separated_log`,
`embedded_credential_url`) so the broadened behavior is itself guarded
rather than moving the hole. `sanitizer-test.sh` now reports 29
positive/negative checks passed (25 original + 4 new assertions across
the 2 new fixtures), and the full 13-contract self-test suite still
passes. The review's Fix guidance offered a second option (removing the
`logs/*.log` allowlist entries entirely) which was not taken, since
broadening the redaction with new test coverage more directly closes the
gap while preserving the allowlisted log path for future producers.

### WR-05: `mac_ci.exs` ships a hardcoded `secret_key_base`, and the loopback-only Postgres cluster uses `--auth=trust`

**Files modified:** `playstead-server/config/mac_ci.exs`
**Commit:** `03a3eb5`
**Applied fix:** Replaced the hardcoded `secret_key_base` string literal
with a value generated via `:crypto.strong_rand_bytes(48) |> Base.encode64()`
at config-eval time, overridable via `PLAYSTEAD_MAC_CI_SECRET_KEY_BASE`
for callers that need a fixed value within one hosted run -- mirroring
the pattern `playstead.mac_ci_fixture.ex`'s `random_text/1` already uses
for its owner password. Added a top-of-file warning comment (not just an
inline one) explaining that this file must never be reused as a template
for a config binding beyond loopback or persisting beyond a single CI
job, covering both the generated secret and the `--auth=trust` Postgres
invocation in `run-mac-verification.sh`. The `--auth=trust` Postgres
invocation itself was left unchanged per the review's own guidance ("no
change required for this ephemeral CI-only path"). The
`wave-0-topology-test.sh`-guarded literals `ip: {127, 0, 0, 1}` and
`server: System.get_env("PLAYSTEAD_MAC_CI_TASK") != "1"` are byte-for-byte
unchanged. `MIX_ENV=test mix compile --warnings-as-errors` succeeded (see
verification-environment note above for how this was checked given the
worktree's missing `deps`/`_build`), and all 13 static contract guards
passed afterward inside the worktree.
