## The live-server blocker (root cause found and fixed)

The `live-server` layer failed identically on every run after `aab1a1c`. `unit`,
`rendering` and `ui` are green, and both Linux jobs are green. Only checkpoint 2's
covering test fails.

**Three stacked bugs, all found on 2026-09-02, all now fixed.** Earlier entries in
this file blamed diverging roots and `chmod` ownership. Both were wrong; the
evidence that suggested them was an artifact of a stage marker whose write was
itself being denied. Superseded, kept here so the same guesses are not repeated.

1. **The XCUITest runner is sandboxed.** Xcode generates
   `PlaysteadUITests-Runner.app` with `com.apple.security.app-sandbox` true and a
   read-only exception for `/`, no write exception. Children inherit the sandbox,
   so `live-server.sh` could neither write into the server root (EPERM) nor
   execute the Elixir toolchain (exit 126). No amount of `chmod` or ownership
   work could have fixed it. Filesystem temporary exceptions are not enough —
   exec is a separate sandbox operation, and its `sbpl` exception is **not
   honored** for an ad-hoc signed runner (verified: the grant is present in the
   built runner and changes nothing). Fixed by `app-sandbox = false` in
   `PlaysteadUITests/PlaysteadUITests.entitlements` (`e9bba53`).
2. **PATH never reached the fixture.** `runFixture` replaces the subprocess
   environment wholesale, and the test process inherits a PATH without Elixir, so
   `mix` failed with 127. PATH now travels in the runtime-config file, and that
   runner-written config is now *authoritative* over inherited env rather than a
   fallback (`7128361`).
3. **A real product bug.** `UITestProfileRootView.init()` consumes and deletes
   the credential handoff, but SwiftUI does not promise one initializer call per
   launch. Two passes race; the loser found the file gone and hit the fail-closed
   `fatalError`. Checking existence first does not fix it — that check *is* the
   race — and `ownedURL` stats the file while resolving the path, so resolution
   must sit inside the same `do` block (this detail defeated two earlier
   attempts). Fixed in `579041e`.

### Diagnostic technique that actually worked

The published evidence contract carries **only `file:line`**, never the assertion
message, so distinguishing causes requires **one assertion site per cause** — that
is what `d2cae9e` did, and EPERM-not-EACCES is what identified the sandbox.
For the app side, `NSLog` does not survive the crash and the `.ips` has no `asi`
field; writing the error to a file from the `catch` is what surfaced it. The
`PLAYSTEAD_LIVE_SERVER_LOCAL_DEBUG` env var does **not** reach the test process —
testmanagerd sanitizes the environment, which is the same reason PATH was wrong.

## Critical Anti-Patterns

| Anti-pattern | severity | Why |
|---|---|---|
| Pushing while a run you need is in flight | blocking | `ci.yml` uses `concurrency: ci-${{ github.ref }}` with `cancel-in-progress: true`. A docs commit cancels the run you are waiting on. Commit locally; push after it lands. |
| Trusting a gate that passes only its own fixtures | blocking | `validate_roadmap` asserted a ROADMAP shape that does not exist in this repo and still passed its suite. Every gate must be exercised against the real file it guards. |
| Guessing at a bounded-evidence failure | blocking | Bounded evidence omits messages and paths by design. When a stage token is too coarse to identify the failing statement, split the stage — do not guess. |
