## The live-server blocker

Eight commits attacked this layer through guesses at `mkdir`, `chmod` and root divergence. All were wrong, and the misleading evidence was itself a symptom: the stage marker whose token those guesses read was written by a process the sandbox was denying.

Four defects were stacked, each hiding the next:

1. **The XCUITest runner is sandboxed.** Xcode generates `PlaysteadUITests-Runner.app` with `app-sandbox` true and a read-only exception for `/`. Children inherit the sandbox, so the fixture could neither write into the server root (EPERM) nor execute the Elixir toolchain (126). Filesystem exceptions alone are insufficient — exec is a separate sandbox operation, and its `sbpl` exception is not honored for an ad-hoc signed runner, verified by observing the grant present in the built runner and changing nothing.
2. **PATH never reached the fixture.** `runFixture` replaces the subprocess environment wholesale, and the test process inherits a PATH without Elixir.
3. **A SwiftUI double-init race.** `UITestProfileRootView.init()` consumes and deletes the one-shot credential handoff, but SwiftUI does not promise one initializer call per launch.
4. **The first sync stored no position.** `SnapshotClient` persisted the catalogue branch and dropped both the curation branch and the as-of cursor, leaving the mirror unable to sync incrementally.

Defects 2, 3 and 4 are product defects, not harness artifacts; 3 and 4 affect any user, not only CI.

## Deviations

- **The plan's UAT mapping table was stale.** Its coarser test names predate the storage and curation splits from plans 06 and 07. The validator's 23 identifiers were treated as authoritative, and each was verified to resolve to a real Swift test function.
- **The accepted run is at a later SHA than the plan's Task 2 commit.** Task 2 authorized publication at `ffb811d`; four subsequent fix commits were required before any run could pass, so the accepted run is `548121e`. The plan's identity requirements were enforced against that exact SHA.
- **Files outside `files_modified` were changed.** Fixing the layer required the Xcode project, a new test entitlements file, the app's sync wiring and UI-testing bootstrap, and a unit test. The plan assumed the layer already worked.
- **A designed sequence was retired.** `syncNow()` routed the first pass through `SnapshotClient` and later passes through `SyncEngine`, asserted by `testFirstSyncBootstrapsFromSnapshotThenSyncEngineTakesOver`. An earlier attempt to make `SnapshotClient` store the cursor was correctly rejected by that test — recording a position after applying only the catalogue would let the next incremental sync skip the curation rows the snapshot carried. `SyncEngine` now owns every pass; `SnapshotClient` retains its tests but no longer has a caller in the app.

## Follow-ups

- **`sync_cursor` regression coverage.** The cursor gap was caught by an end-to-end layer, not a unit test. A direct test that a fresh bootstrap records a resumable position would catch it faster.
- **Two dormant gates.** `wave-0-topology-test.sh` carries a stale literal, and `plan-05-surface-contract-test.sh` has identity and launch-environment drift. Both are out of this plan's scope and neither currently protects anything.
- **Layer ordering.** `ui` is roughly 26 of the job's 32 minutes and has never failed. Running `live-server` first would fail fast, but it touches the keyboard-mode trap composition and the topology gate's ordering assertions.
