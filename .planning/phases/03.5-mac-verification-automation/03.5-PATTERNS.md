**Failure-only artifact pattern** (lines 73-79):

```yaml

    name: wallaby-screenshots
    path: playstead-server/tmp/wallaby_screenshots
```

Reuse `if: failure()` and `upload-artifact@v4`, but upload only a sanitized allowlisted staging directory with short retention. Raw `.xcresult` bundles need sanitization because they can include paths, environment, UI labels, and attachments. Never stage handoff files, Keychains, credentials, `.env`, databases, object bytes, ROM names/hashes, or raw server responses.

**Critical divergence:** `.github/workflows/ci.yml:86-145` proves Docker deployment on Linux. Preserve it. The new Mac job starts native PostgreSQL and Phoenix; it must not try to move Compose onto a standard ARM64 Mac runner.

**No direct analog:** the repository has no one-build/four-`test-without-building` aggregator, `xcresulttool` allowlist verifier, evidence sanitizer, environment-fingerprint writer, release-hook binary scanner, or candidate-only snapshot refresh workflow. Implement those from the locked research patterns, with fixed layer names, aggregated exit codes, no retry, and a final nonzero exit if any layer or discovery assertion failed.

Preserve the production service/envelope/newest-wins behavior when no explicit scope is supplied. When a disposable file Keychain is supplied, add `kSecMatchSearchList: [scope]` to every match/copy/update/delete/enumeration query—not only the first load query.

**Crash-safe update/add/prune pattern** (lines 156-207):

```swift

    return pruneAccounts(otherThan: credential.deviceID)
```

**One-use bootstrap constraints:** under the UI-testing compilation condition only, validate the handoff file is owned by the run and mode `0600`, decode the fixed credential schema, delete the file before calling real `storeCredential`, then launch through the normal `loadCredential` path. ## Shared Patterns

### Test Isolation and Cleanup

**Sources:** `AppPaths.swift:26-47`, `SyncEngineTests.swift:21-36`, `.github/workflows/ci.yml:28-40`

Apply unique per-test/run roots, bounded readiness polling, exact service health checks, and cleanup in XCTest teardown plus shell trap. Failure cleanup must not depend on the test layer succeeding.

### Non-Vacuity Before Outcome

**Sources:** `SyncEngineTests.swift:99-131`, `pairing_controller_test.exs:9-32`, `03-UAT.md:94-110`

Every UAT-mapped test must first prove the fixture/test/surface exists: exact nonzero counts, exact state set, expected test identifier discovered, settled sentinel present, expected ID inventory nonempty and unique.
