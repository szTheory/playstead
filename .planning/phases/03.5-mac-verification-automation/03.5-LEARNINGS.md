# Phase 03.5 Learnings: Mac Verification Automation

The phase's own theme — proving Mac behavior by machine instead of by hand — turned
out to apply recursively. The gates this phase built had to be checked for whether
they actually run, and four of them did not. That is the dominant lesson here, and
it generalizes past this phase.

## Decisions

### One unfiltered required macOS job on every push and PR
Pin a numbered `macos-*` image and an explicit Xcode version; assert `sw_vers`,
architecture, and `xcodebuild -version` before testing.

**Rationale:** Hosted images are mutable third-party infrastructure. A drifting
image silently changes what "verified" means, so the fingerprint is asserted rather
than assumed.
**Source:** 03.5-CONTEXT.md (D-01)

### Keep Linux compose-smoke; run native PostgreSQL 17 + Phoenix beside XCUITest
Hosted macOS runners cannot run the Docker Compose stack, so deployment topology
and Mac client/server behavior are proven by two different mechanisms.

**Rationale:** Neither proof substitutes for the other. Collapsing them would have
meant faking one.
**Source:** 03.5-CONTEXT.md (D-04)

### CI never records snapshots; baseline refresh is manual, candidate-only
CI fails on a missing reference. Refresh is a `workflow_dispatch` workflow with
`contents: read` that emits candidates and asserts `git diff --exit-code`.

**Rationale:** A harness that can rewrite its own baselines cannot detect a
regression — it absorbs one.
**Source:** 03.5-CONTEXT.md (D-17), 03.5-SECURITY.md (T-03.5-07)

### Accessibility identifiers never derive from content
Identifiers depend on role and surface, never on labels, game titles, filenames,
paths, hashes, credentials, or coordinates, with an independently authored inventory.

**Rationale:** Content-derived identifiers leak user data into diagnostics and make
tests fail for the wrong reason when content changes.
**Source:** 03.5-CONTEXT.md (D-18), 03.5-SECURITY.md (T-03.5-10, T-03.5-14)

### Split Phase 3 UAT checkpoint 10 rather than claim its broad wording passed
The automated portion covers keyboard reachability and machine-checkable live
accessibility-tree properties; the physical-controller portion stays blocked.

**Rationale:** Marking a broadly worded checkpoint "passed" on partial evidence
converts a known gap into an invisible one.
**Source:** 03.5-CONTEXT.md (D-23), 03.5-09-SUMMARY.md

### Out-of-scope UAT items stay `blocked`, and Phase 3 stays `partial`
Checkpoint 4 (scope decision), 7 (real emulator + game bytes), 8/9 (physical
hardware), 14/15 (Developer ID) remain blocked; Phase 3 is not marked complete
merely for having no *pending* checkpoints.

**Rationale:** "No pending items" and "done" are different states. Conflating them
launders unfinished work into apparent completion.
**Source:** 03.5-CONTEXT.md (D-25), 03.5-VERIFICATION.md

### The contract gate enumerates guards from the directory, not from a list
`run_contract_self_tests()` globs `tests/*.sh` rather than naming each guard.

**Rationale:** A hand-maintained registry adds a step someone must remember. With
enumeration, a new guard is picked up by existing. This was chosen specifically
because the phase had just demonstrated that remembering does not scale.
**Source:** commit 665a62f, 03.5-SECURITY.md (Audit Notes)

## Lessons

### A guard that exists but never runs is not a mitigation
Ten static contract guards were written, committed, and reachable only through CLI
flags nothing invoked. CI called `run-mac-verification.sh` exactly once, with
`--run-four-layer-verification`, which called none of them. Two had silently drifted
out of agreement with the code they guard.

**Context:** Found by the regression gate during phase close, not by CI. Fixed in
665a62f by adding `--self-test-contracts` and wiring it into `ci.yml` ahead of the
build.
**Source:** 03.5-REVIEW.md (WR-03), 03.5-SECURITY.md (Audit Notes)

### A missing command exits 127, and `if cmd` reads that as "clean"
`wave6-swift-semantic-test.sh` used ripgrep, a Homebrew install absent from the
macos-26 image. Its production checks were shaped `if rg -q "$pattern" "$source"`,
so on CI every one of them would have reported "pattern absent" while checking
nothing. It passed locally, which is why it survived until a gate finally ran it.

**Context:** Caught on the contract gate's *first* hosted run. Only the guard's
negative control — asserting the matcher catches a known-bad input before trusting
it — turned a silent pass into a loud failure.
**Source:** CI run 33710448156, commit 541520b

### The claimed control must match the enforced control
`verify_complete_hosted_run` binds a run's evidence manifest to its real identity
and was fully implemented and correct — but nothing invoked it. The threat register
described it as *the* fail-closed control with no human carve-out, so an opt-in CLI
was strictly weaker than what the register promised.

**Context:** The distinction that made this blocking: T-03.5-22/23/24 explicitly
name human observation as their control, so human execution *is* the mitigation.
T-03.5-01 and T-03.5-20 did not.
**Source:** 03.5-SECURITY.md (T-03.5-01, T-03.5-20), commit e50a12f

### Local verification and hosted verification are different claims
App-hosted tests could reach the developer login Keychain, proven by `securityd`
ACL evidence and repeated password prompts. Local Mac verification was stopped
permanently for the phase; all app-launching acceptance moved to exact hosted SHAs.

**Context:** Later reinforced by the ripgrep defect, which passes locally and fails
hosted. "Passes on my machine" and "passes on the runner" are independent facts.
**Source:** 03.5-05-SUMMARY.md, 03.5-08-SUMMARY.md

### Sandboxed test runners hide product defects behind harness symptoms
Eight commits chased `mkdir`/`chmod`/root-divergence guesses at the live-server
layer. All were wrong: the stage marker those guesses read was written by a process
the sandbox was denying. Four defects were stacked, each hiding the next.

**Context:** Two of the four (a SwiftUI double-init race consuming the one-shot
credential handoff, and the first sync storing no cursor) were product defects
affecting any user, not CI artifacts.
**Source:** 03.5-09-SUMMARY.md ("The live-server blocker")

### Compilation passing is not the same as the toolchain passing
The WR-05 config fix compiled cleanly and failed `mix format --check-formatted` in
CI. Verifying compilation alone missed it.

**Context:** A full `mix precommit` locally would have caught it before the push.
**Source:** CI run 33710448156, commit bb9f52c

## Patterns

### Negative control before trusting a matcher
Assert the matcher detects a known-bad input before running it against production
sources. `if not forbidden.search(KNOWN_BAD): fail`.

**When to use:** Any guard whose production check is shaped "if pattern found,
fail." Without the control, a broken matcher and a clean codebase are
indistinguishable. This is the single mechanism that caught the ripgrep defect.
**Source:** wave6-swift-semantic-test.sh, SnapshotHarnessCanaryTests.swift

### Prove a new fixture fails against the *old* implementation
When broadening a check, run the new fixtures against the pre-fix code and confirm
they fail.

**When to use:** Every regression test added alongside a fix. It distinguishes a
test that detects the bug from one that merely describes current behavior. Used to
validate the WR-04 sanitizer fixtures (they fail with "colon-separated
secret-bearing log line was not redacted" against the old sanitizer).
**Source:** commit db29a03, 03.5-REVIEW-FIX.md

### Guards depend only on stdlib and preinstalled tooling
No ripgrep, no PyYAML. `python3` and POSIX tools only.

**When to use:** Any check that runs in CI. A guard needing an uninstalled tool is a
guard that does not run — and worse, one that may pass vacuously. When comment text
must be excluded from a scan, strip comment lines rather than reaching for a parser.
**Source:** commits 541520b, e50a12f

### The wiring is itself guarded
`four-layer-topology-test.sh` asserts that `ci.yml` invokes `--self-test-contracts`
*and* that it precedes the build, and that `verify-hosted-evidence.yml` retains its
`workflow_run` trigger, permissions, and validator invocation.

**When to use:** Whenever a gate's value depends on staying wired. Mutation-test each
marker: delete it and confirm the guard fails. A guard nobody can accidentally
unwire is worth more than one that merely exists.
**Source:** commits 665a62f, e50a12f

### Derive identity inputs from the source of truth, never hand-author them
`verify-hosted-evidence.yml` derives its run record from the GitHub API view rather
than constructing it.

**When to use:** Any validator proving two artifacts agree. If both inputs are
authored by the same process, the check proves only self-consistency.
**Source:** .github/workflows/verify-hosted-evidence.yml, commit e50a12f

### Fail-closed evidence with per-item non-vacuity
`verify_layer_result` requires `discovered == True`, `execution_count == 1`,
`skipped == False`, `outcome == "passed"` per named test, plus
`executed_test_count > 0` per layer.

**When to use:** Any "the tests passed" claim. Without per-item assertions, an empty
allowlist or a silently skipped suite satisfies "no failures."
**Source:** run-mac-verification.sh, 03.5-VERIFICATION.md

## Surprises

### The gate found a real defect on its very first hosted run
`--self-test-contracts` was added to close a known gap. Its first execution on the
macos-26 runner immediately failed on a defect no local run could see, and correctly
skipped the ~30-minute build rather than burning it.

**Impact:** Converted an abstract argument for wiring guards into a demonstrated one
within a single CI cycle.
**Source:** CI run 33710448156

### Four fail-open defects in one phase, all the same shape
Guards unreachable from CI; a guard whose tool was missing; a validator's fixture
meta-test unwired; and the hosted-evidence validator itself unwired. Each was written
correctly and each protected nothing.

**Impact:** Reframed the phase's risk. The hazard was never bad checks — every one of
these was well-written — it was checks that do not execute.
**Source:** commits 665a62f, 541520b, 66947c2, e50a12f

### A guard written to prevent this exact failure was itself fail-open
The first version of the `verify-hosted-evidence.yml` wiring guard scanned the whole
file for marker strings. The workflow documents the very flags it wires, so a header
comment satisfied a marker whose real invocation had been deleted — the unwire test
passed when it should have failed.

**Impact:** Fixed by stripping comment lines and checking executable content only,
then mutation-testing all four markers. Strong evidence that this failure mode is
easy to reproduce even while actively looking for it.
**Source:** commit e50a12f

### Two guards had drifted, but neither was a behavior regression
`wave-0-topology-test.sh` required a literal `server: true` that plan 08 had
deliberately made conditional; `plan-05-surface-contract-test.sh` did not know about
plan 09's D-18 test, plan 06's per-session identity, or plan 07's AX-group change.
In every case the shipped code was correct and the guard was stale.

**Impact:** The failure mode is not "code broke" but "the check stopped describing
the code," which is invisible precisely because nothing runs it.
**Source:** commit 04f38cc

### The plan-05 guard's meta-test caught an error introduced while fixing it
Moving the focus modifier last made a missing marker's `-1` index read as
"earliest," so the ordering check would have passed vacuously. The guard's own
meta-test rejected it.

**Impact:** Direct evidence that meta-tests on guards pay for themselves. Fixed with
an explicit presence check before the ordering comparison.
**Source:** commit 04f38cc
